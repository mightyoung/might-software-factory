# Fixed recovery fixture contracts

These resources are exclusively for `msf_ci_risk_recovery`, with canonical runtime `msf_ci_recovery_runtime` and separate capture runtime `msf_ci_recovery_capture_runtime`. No NAS or existing-role execution is permitted by this fixture.

`CiPg18SourceFixture.openRecovery` reuses original fresh-install migrations, identity, enforcement and foundation initialization under a fixed private spec. Unlike SOURCE, recovery bootstrap creates no HMAC key, servlet request, `CapturedHumanRequest` or framework session. SOURCE behavior retains its existing fixed target, resource, key/session construction and evidence contract. No reverse dependency on recovery-directory Java classes is introduced.

Canonical grants reuse the exact SOURCE resource with two fixed database/role literal substitutions. `canonical-extra-grants.sql` adds only the five original history columns needed by independent worker attach checks; no history writes. The verifier expects 31 relations for RECOVERY versus SOURCE's 30. Function rights remain the same 22 exact ordinary signatures, with no trigger-function or blanket grants.

`capture-grants.sql` carries the existing capture lane's narrow reads, cause SELECT/INSERT and the exact original instant predicate EXECUTE. Recovery checks effective privileges over every public relation/column and function, role attributes/memberships/ownership, database/schema privileges and grant option. PUBLIC function inheritance is preserved and explicitly compared, not described as converged least privilege for the entire instance. Source/native ACK share their existing canonical role and source SQL permissions; consumer attachment does not make that role a SQL sandbox without business-write grants.

`CiPg18RecoveryFixture.bootstrap` is parent-only, takes the independently validated parent target and distinct capture password, and creates the active SERVICE principal under the actual global security guard. `bootstrapState` exposes private owned fixture identifiers to the orchestrator for fixed worker config, never public evidence. `observer` starts a real independent READ ONLY transaction; bootstrap mutations go through a different private transaction path.

`attachProducer` first verifies the fixed target/schema/history/ACLs, then creates fresh random keys and its synthetic current source session in that producer JVM using the existing guarded `CiPg18SourceSession.create` helper. This is not password-login/HTTP proof. `attachRecovery` validates using canonical/capture credentials only and never reads admin/HUMAN getters, creates keys or captures a HUMAN request. Its inert real source participation graph is composed by the separate graph lane.

The worker verifier calculates checksums with the pinned Flyway `ChecksumCalculator` over original classpath SQL and compares exactly the 21 fresh-install history rows. It neither reconstructs V9 nor runs Flyway migrate/repair during attachment. Current constraints, source FORCE-RLS, cause table/FKs/triggers and ENFORCING activation are also checked. Parent-only success evidence contains fixed database/version/image, original script checksums and schema/rights booleans; case/process/cleanup acceptance belongs to the orchestrator and runner.

Implementation status: source only, awaiting coordinated compile and real owned PostgreSQL acceptance. No database was executed while preparing these files.

Failure evidence uses the fixed recovery filename/database for RECOVERY only. Source bootstrap phases that do not exist in the recovery contract map to canonical-rights (runtime/schema) or open (base identity/foundation); unknown phases remain unknown. The private already-recorded failure marker prevents outer bootstrap from overwriting a more precise inner failure. Recovery fixture emits only whitelisted phases and a bounded five-character SQLState; setup failures retain only that safe state, never the raw exception. SOURCE filename/database/phase behavior is unchanged.
