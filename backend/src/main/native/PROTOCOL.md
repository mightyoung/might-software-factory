# Candidate native scanner broker V1

This repository source has not been accepted or installed as a privileged resource. Ordinary CI compilation and negative fixtures do not prove ARM/Bookworm compatibility, kernel isolation, scanner verdicts or restart recovery. No install target, daemon, capability grant or setuid operation is provided.

The executable accepts exactly `broker {launch|inspect|quiesce|probe} PROFILE_SHA256 REALM_UUID SLOT_ID EXECUTION_UUID`. All paths are derived from fixed root-owned namespaces. Real UID/GID must match the immutable profile; the scanner UID is distinct and nonzero. The app receives no scanner pipe FD and no privilege. Missing provider/profile/realm/controls denies.

The full 32-byte random challenge appears in every frame. A public DTO or a parsed frame is not acceptance. A pinned, audited broker plus independently accepted actual resources and denial probes supplies kernel observations. Java checks CHILD before GO and IMAGE before bytes; the ProcessBuilder PID is the supervisor only.

## Frame encoding

All integers are unsigned big endian unless the corresponding Java field is a signed bounded positive long. Payload length is u32 (1..32768), followed by u16 version=1, u16 type, u32 directional sequence (starts at 1), challenge[32], execution UUID[16], realm UUID[16], profile SHA256[32], u16 slot length plus 1..64 ASCII identifier bytes, descriptor SHA256[32], then exact body. After END and every one-shot request Java half-closes the control input; native rejects any trailing byte before responding. Control traffic is capped at 256 KiB per session; DATA is separately bounded by exact declared bytes. No raw scanner output is exported.

Types are PREPARE=1, PREPARED=2, START=3, CHILD=4, GO=5, IMAGE=6, DATA=7, END=8, RESULT=9, INSPECT=10, QUIESCE=11, RECOVERY=12, PROBE=13, PROBE_RESULT=14, ERROR=15. Unknown, duplicate, reordered, truncated, over-limit or trailing fields are errors. There is no READY_V1 compatibility path.

Bodies:

- PREPARE: tenant,intent,file,source-attempt,scan-attempt,quarantine-allocation,scratch-allocation UUIDs; u64 old technical version; u64 planned epoch; generation SHA256[32]; original quarantine observation SHA256[32]. Descriptor field is zero.
- PREPARED: boot UUID; u64 actual supervisor PID/start ticks; u64 stable lock device/inode; control SHA256[32]. No scanner child exists.
- START: u32 canonical descriptor length, exact files codec canonical descriptor, u64 exact input bytes, expected content SHA256[32]. Common descriptor is the exact canonical hash. The native gate validates every prospective plan/claim field and durably writes START_INTENT before atomic clone3.
- CHILD/IMAGE/RECOVERY: fixed kernel facts body below. GO is empty. DATA is 1..30000 bytes; END is u64 input bytes plus SHA256[32].
- RESULT: i32 exit, u64 input bytes, input/stdout/stderr SHA256 (32 each), u64 stdout/stderr bytes, u8 reason (0 clean,1 rejected,2 error), kernel facts. Successful proof requires exact exit0, empty outputs, matching bytes/hash, actual IMAGE and normal REAPED/drained facts.
- QUIESCE/INSPECT: u8 descriptor presence; if 1, u32 length and original committed canonical descriptor; if 0, the exact descriptor must already exist natively (or zero descriptor for an unclaimed prepared control). Common descriptor binds the expected original hash. Recovery cannot invent a business claim from a PID.
- PROBE: u8 closed enum ordinal (Java ImmutableContainmentProfile.Probe). CLEAN_CONTROL/EICAR_CONTROL use built-in fixed bytes, never arbitrary caller bytes or fabricated SQL identities. PROBE_RESULT is u8 result (0 observed success), i32 scanner/control exit, u64 bytes, input SHA256[32], kernel control SHA256[32], effective fixed argv/environment policy SHA256[32] (109-byte body).

Kernel facts body is 315 bytes: boot UUID; u64 supervisor PID/start; u8 child-present,u64 child PID/start,u8 absent reason (0 observed/2 not-recorded); five u64 namespace inode IDs (pid,mnt,net,ipc,uts; zero transport value becomes null); cgroup UUID; u64 mount ID/inode; pids policy SHA256; u64 pids.current; four u8 flags (populated,continuous protected pids policy,no migration/future entry,exclusive slot lock); slot-lock SHA256; u8 permanent STOP plus STOP SHA256 (all-zero only when absent); seven flags (CHILD,IMAGE,wait/reap,input/stdout/stderr drains,interrupted output discarded); u8 ProcessState ordinal; kernel-control/report SHA256; u64 UTC epoch seconds; u32 UTC microseconds. Strict bits are 0/1. KERNEL_ABSENT cannot produce CLEAN or successful drains and cannot invent child IDs.

## Fixed resource namespaces

Profiles are immutable content-addressed files `/etc/msf-scanner/profiles/<full-lowercase-SHA256>`; the content omits its own ID. Closed LF ASCII key=value fields: format=MSF_SCANNER_BROKER_PROFILE_V1, realm-id, slot-count (1..2), caller-uid/gid, scanner-uid/gid, memory-bytes, scratch-bytes, max-bytes, cpu-seconds, max-pids, max-fds, scanner-sha256, slot.0.id and slot.1.id only for two slots. The closed resource-count (6..64) and resource.N.path/resource.N.sha256 inventory lists the executable, exact main/daily/bytecode CVDs, libclamav, package manifest and every other staged file. Paths are canonical relative artifact names under scanner/, definitions/, lib/, usr/lib/ or etc/; scratch files, symlinks, unknown files and writable resources are rejected. Java validates the configured slot0 host paths/hashes against this inventory and includes every physical slot in the generation manifest. Native walks opened directory descriptors and checks all files before/after execution, then verifies actual executable/library mapping inodes and hashes before forwarding bytes. Current admission validates candidate limits; retained recovery resolves the exact old hash and does not require current definitions or signing.

Realm roots are `/var/lib/msf-scanner/realms/<UUID>/slots/<slot>` with root-owned stable slot.lock, executions, realm-binding and staged rootfs. Cgroup parent is `/sys/fs/cgroup/msf-scanner/<realm>/<slot>`. Realm-binding records physical lock/control/rootfs/cgroup-parent device/inode identities. Distinct slots reject rootfs/cgroup aliases. The cgroup execution name is the never-reused execution UUID. Control capacity is bounded and old fences are never pruned automatically. Files use Java FileChannel locks for both writer/recovery; native slots consistently use flock.

Integrity hashes use fixed Linux AF_ALG type=hash,name=sha256, no handwritten crypto, external command, linked crypto dependency or fallback. Existing kernel provider availability is mandatory and is tested with standard empty/abc/million-a vectors. This does not authorize loading a module or installing a provider.

## Portable protected control records

Disk ABI `MSFC0001` uses magic[8], u16 version=1, u16 closed kind, u32 payload length, SHA256(payload)[32], then exact canonical payload; all numbers are big endian. Kinds 1..10 are PREPARED, PREPARED_KERNEL, PLAN, DESCRIPTOR, START_INTENT, CHILD, GO, STOP, REAPED, RECOVERED. Unknown versions/kinds, trailing bytes, truncation and digest mismatch deny; raw C structs are never accepted. SHA supplies integrity only; authority comes from the pinned root-owned control store/caller boundary.

PREPARED binding payload is challenge32, execution16, realm16, profile32, descriptor32, u16 slot length and ASCII slot. Kernel control payload is 282 bytes: boot16; policy/control/lock/STOP/report SHA256 (five32); twelve u64 values (supervisor PID/start, child PID/start, five namespace IDs, cgroup mount/inode/pids.current); nine strict u8 flags (populated,STOP,CHILD,IMAGE,reaped,input/stdout/stderr drained,output discarded); u8 ProcessState. Typed decoders reject inconsistent state; these values alone do not grant readiness.

Non-STOP records are written/fsynced to a protected pending workfile then atomically published with renameat2 RENAME_NOREPLACE and directory fsync. Thus no partial START_INTENT final name can precede clone3. PLAN, PREPARED_KERNEL and PREPARED are durable before ACTIVE is published. STOP presence remains irrevocable, including interrupted writes: under the exact slot/execution locks only a byte-exact expected prefix may be completed on the same inode. It is never removed/replaced. Recovery works independently of current definitions/signing and retains every charge on UNKNOWN. Slot locks use native flock consistently; ordinary writer/recovery locks both use Java FileChannel, with same-JVM ownership preventing accidental POSIX lock release by another descriptor close.

The native execution policy V2 hash is SHA256 of ASCII `MSF_CLAMSCAN_CONTAINMENT_V2\n`, each actual argv (including `/scanner/clamscan`) plus LF, then `LC_ALL=C\nTZ=UTC\nmemory.swap.max=0\nparent-death=SIGKILL/ARMED_GO_V2\nsupervisor-effective-cap=CAP_KILL\n`. The same C argv builder supplies execve and the hash; Java requires exact equality with its own policy encoding. Kernel control hashes additionally bind actual staged resource identities/hashes and kernel SHA provider observations. Limit probes bind observed OOM/PID counters, actual CPU usage and charged zombie evidence; scratch exhaustion uses several bounded files to distinguish filesystem capacity from per-file RLIMIT_FSIZE. The orphan-reaper fault probe kills the pipe-owning supervisor after atomic clone but before CHILD, reacquires the physical lock and invokes the production KERNEL_ABSENT path without reaping that orphan itself. These privileged paths have NOT been executed or accepted by ordinary protocol tests.


## Post-review lifetime and swap constraints (candidate V2 policy)

The broker is a single-threaded executable; the thread performing clone3 also owns the setup pipes and the supervision deadline. The child installs a trusted finite real-time setup timer (SIGALRM handler calls `_exit`, explicitly unblocked) before credential/mount setup. After final setgroups/setresgid/setresuid and NO_NEW_PRIVS it sets PR_SET_PDEATHSIG(SIGKILL), confirms PR_GET_PDEATHSIG, then installs seccomp. No trusted credential change follows. The sandbox denies prctl, capset and all credential-changing syscalls; clone namespace flags and clone3 are denied. NOSUID rootfs plus NO_NEW_PRIVS excludes privileged exec clearing the protection.

The existing private setup handshake is now ARMED_GO_V2: the child closes all inherited peer/control ends with close_range, retaining only GO-read fd100 and ARMED-write fd101. Only after the installation above does it send byte 0xa1 and await byte 0xa2 with its own finite monotonic deadline. The single creating supervisor must receive ARMED, check actual child identity, persist/emit bound CHILD, and obtain the bound application GO before it generates the private GO byte. Probe children use the same installation/ARMED ordering. EOF, wrong marker, deadline and setup errors call trusted `_exit(126)`; no scanner exec or input occurs. The setup timer is disabled only after this handshake: SIGALRM is blocked, the timer is cancelled, any pending alarm or elapsed monotonic deadline fails with `_exit`, then SIGALRM is unblocked; the broker deadline remains authoritative while alive and parent-death handles its loss. No host-PID getppid comparison or one-shot pidfd poll is used as a race proof. Parent death before installation cannot produce a post-install GO; after installation it triggers SIGKILL. This is source reasoning, not evidence of actual target signal delivery/reaping.

Every fresh execution writes and reads back memory.swap.max=0 before clone or GO. Admission and retained inspection both require the exact `0`/`0\n` value from the exact cgroup; missing, unsupported, unreadable or mismatched values fail closed. There is no configurable swap budget or assumption that missing swap files imply no swap. Fresh groups are empty before entry. The cgroup policy domain is MSF_PIDS_POLICY_V2 and hashes actual memory.max, pids.max, cpu.max and memory.swap.max readback plus protected cgroup identity. Retained old V1 kernel records therefore mismatch and return UNKNOWN, keeping charges; no prior marker is rewritten as a V2 fact. Neither wire/public DTO nor protected disk record shape changes. Current actual pinned broker/profile resource acceptance must be redone for the new executable/policy; a compiled candidate cannot grant it.

The added ordinary pipe tests check ARMED ordering and wrong/EOF/deadline failure only, and ordinary-file swap fixtures check strict parser/readback only. They do not prove kernel cgroup support, parent-death delivery to PID namespace init, descendants/reaping, LSM permission or scanner compatibility. Required actual target fault cases remain parent kill before installation, between installation and ARMED, before/after GO and during blocked scanner work, plus inability to clear protection and actual memory/swap enforcement. No privileged probe was run for this change.

The ordinary fork-child fixture additionally runs the actual PR_SET/GET and seccomp filter under its unchanged nonroot credentials, then verifies EPERM for clearing PDEATHSIG and no-op same-UID/GID credential syscalls. The fixture owns and waitpid-reaps every child. Separate setup timer fixtures cover successful cancellation, pending alarm, elapsed deadline and trusted timeout exit. These are normal-process syscall checks only, not PID1/namespace/LSM/cgroup fault acceptance. Generation resource canonical encoding V2 explicitly includes the effective containment policy SHA256.

New launch/probe admission checks real capget v3 Effective CAP_KILL before resource allocation, again in each actual creating supervisor immediately before clone3, and immediately before GO. Different scanner UID and the unchanged user namespace make this a necessary kernel signal-permission prerequisite; effective UID zero, permitted/inheritable capability bits or a same-UID fixture do not substitute. No capability is granted or modified. Inspect/quiesce retained recovery deliberately does not require this new-launch capability; its existing exact identity/quiescence checks remain. The fixed expected capability requirement is included in both Java/C effective policy encodings. LSM permission and actual cross-UID/PID1 signal delivery/reaping still require target fault probes. The ordinary capmask fixture checks only the exact Effective bit, not signalability.
