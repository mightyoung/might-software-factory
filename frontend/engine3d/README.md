# Might 3D Engine · Phase 1a

独立 Three.js/TypeScript 程序化设备预览。运行 `npm ci && npm test && npm run build && npm run check:bundle`；使用 `npm run dev` 打开沙盒。主工作台和 Office 不引用它，本切片没有生产菜单入口或后端权限、数据、发布实现。

选择列表中的设备可将三维相机移到对应稳定 ID；不支持 WebGL 2 时仍能查看和选择同一份场景数据。渲染只在相机、设备状态、视口尺寸或恢复时触发。渲染器、事件、调度器、几何体和材质属于每个挂载实例；不共享租户或浏览器持久状态。二维列表是原型保底，不等于完整二维地图。

后续补 GLB 资产校验、引用计数、LOD/解码、模型管理、预制体及大屏双态。当前未验证 50 次模型切换实机显存趋势、长期投屏性能或生产可用性。280 KiB 是独立预览资产硬门槛，和主工作台预算无关。


Starter v1 首批加入传送带、廊道、机械臂和螺旋传送机。预览可切换传送带的 4 / 8 米尺寸，实际重建结构和共享资源；端口是设备的局部坐标（米），还不是业务或物联绑定。初代盒体/圆柱和文档仍可读。

节拍仿真目前为独立、纯 TypeScript 串行线内核，详见 [sim 说明](sim/README.md)。它纳入类型检查和回归，未接入浏览器预览或 Worker，不会增加运行态包体积。

本地模型预览支持自包含 GLB 2.0 的无纹理单三角网格（最多 8 MiB、10 万顶点及 15 万面），显示从顶点实际计算的米制包围盒。文件只在浏览器本地内存处理，不外传或入库；支持校验失败保留前一模型以及返回合成场景。测试覆盖 50 次本地模型切换和释放，不视为实机显存长期稳定认证。纹理、材质、节点变换和压缩等需待后续受控解析。

交互工具 v3：选四类参数化设备之一，可用五面按钮按 0.5 米增减，水平保持对侧、+Y 保持底面，基于尺寸参数重新生成结构。还没有画布拖拽手柄和墙线/区域编辑器。GLB 提供显式米/毫米报告；异常大坐标只提醒核对，不按阈值自动转换。不扩大既有 GLB 静态无纹理子集。

顶视平面草稿支持鼠标/触屏点选及 X/Z 数值键盘录入、连续墙段、0.1/0.5/1 米网格、正交锁定与闭合区域的平方米数。拒绝重复墙段、零长线及自交区域，保留失败草稿。此类几何在页面内存中，无业务发布、3D 墙体或复合楼层能力。

选中参数化设备后也可拖动视口金色面手柄。沿局部面外法线投影计算变化，抬手才提交，Esc/失焦取消不写入草稿；键盘面板仍保留。视角过平时隐藏该方向的手柄，避免几像素移动触发不可控尺寸跳变。

顶视图完成墙段后会同步生成三维墙体预览（3 米高、0.2 米厚）；替换几何时释放上一组。查看独立 GLB 时暂时隐藏场景墙体，返回合成场景后恢复。区域仍为二维草稿，未写入正式场景文档。

会话模型库允许把已验证 GLB 显式保留在当前页面内存，按 SHA-256 去重，最多 8 件/32 MiB；可重新预览和移除。无私有对象存储、刷新后保留、跨租户、正式资产引用或后台上传。

Studio 草稿 v1 可离线导入/导出小型 JSON，包含当前设备与已闭合的顶视图墙/区。导入先完整校验版本、上下限、拓扑及区域面积；无效文件不覆盖现有画面。不是发布快照或后台保存，GLB 原文件或会话资产不随草稿打包。

离线 Player：Studio 可生成独立放映 JSON，`player.html` 读入后只展示设备与墙体（区域仅计数）并支持键盘聚焦。文件摘要用于发现变更，不是签名、访问授权或生产发布回执；放映不加载 Studio 编辑器入口，不接外部网络。在线发布、身份权限与配置版本依旧另验。

常见导出器兼容切片：无纹理单静态网格现可读取有界单链父节点变换、法线、有效步长与简单不透明材质声明。尺寸按变换后的顶点计算，预览颜色仍统一；不接收多分支场景、贴图、外链、动画或压缩扩展。

有界多网格 GLB：单文件最多 4 个互不复用的静态网格、16 个无环节点，每网格一个三角面图元。将各网格变换合并到统一预览，按实际几何报告总尺寸和面数。不扩大 8 MiB、总顶点或总三角面上限，仍不支持贴图、外链、压缩扩展或动画。
合成视频窗口使用 Canvas captureStream 的本地画面验证最多 4 活动流、LRU 释放、隐藏 15 秒回收和页面清理。Chrome 用实际 MediaStreamTrack 验证驱逐与停止；不连接摄像头、GoWVP/ZLMediaKit 或真实 H.264/H.265。

离线 Player 设备巡检需手动启动，按快照设备顺序前 20 项逐个聚焦（每项 3 秒）；手动选设备、暂停或页面隐藏都会清理定时器。此时尚不是 Studio 自定义机位、样条动画或跨屏编排。

Studio 可编排有名称的设备机位及 1–30 秒停留，按添加顺序进入离线放映。机位指向同一快照设备，不持有外部控制链接；超限、重复、未知设备会拒绝。老快照无机位时仍按原设备顺序。

Studio 可选择设备、告警、墙体、区域四种静态放映卡；从快照实际计算，支持全关，旧快照默认四张。Player 单独构建，超宽屏有自适应布局，不绑定实时数据或运行自定义 HTML。

合成发布验收用两组内存角色测试独立发布/读取权限、跨租户拒绝、预期版本冲突和历史不可变，允许从已授权读取的版本导出离线 Player 文件。它不是登录鉴权、生产发布或数据存储。

### Meshopt 离线技术验证（尚未接入 Studio／Player）

独立 `core/meshoptPreview.ts` 只验证一个极小兼容子集：GLB 2.0 必须声明 `EXT_meshopt_compression` 为必需扩展，模型只有一个恒等节点、一个无索引的三角网格、连续 float32 POSITION（12 B 步长），`ATTRIBUTES/NONE`，单一内嵌压缩区间占满声明的 BIN（仅允许末尾 0–3 字节补齐），没有外链、贴图、材质、其他扩展或节点变换。先限 JSON 4 KiB、压缩源 1 MiB、65,535 顶点（786,420 解压字节），再用项目锁定 Three 的 Wasm 解码；结果交回普通静态 GLB 校验，实际三角面数、坐标和尺寸从几何重算。浏览器现有导入入口仍拒绝此类文件，放映与打包资源不变。

测试用项目已有锁定开发传递依赖 `meshoptimizer@1.1.1`（MIT）对原创合成三角面执行 `encodeGltfBuffer(..., "ATTRIBUTES", 0)`，不使用第三方模型文件。当前仅证实 Node 上的窄格式、预算限制及内容校验。Worker、浏览器实跑、其他 Meshopt 模式、资源预算和正式模型管理联动另行验收。
