# 普通业务台账可视化配置设计确认稿

2026-11-20，访谈 Q1–Q36 已确认。本文是普通台账、单台账流程、事件串接、详情页和权限的产品设计依据。Q34–Q36 确认功能权限和数据权限由两个引擎独立管理。第 7 节分别列出可复用组件，第 8 节是待执行的验收场景。

**有配置权限的人应能在页面上从空白建立并发布一种普通业务台账，全程无需为这本台账改代码或部署应用。** 一套流程定义只办理一种台账，同一种台账可以被多个流程显式引用。涉及另一本台账的业务通过事件串接各自的流程。Q22–Q25 确认的单台账模型取代了访谈早期在同一画布切换台账的设想。

## 1. 从空白建账到业务使用

1. 在设计器中新建台账，或引用已有台账。复制结构会创建独立的台账、列表和授权配置。引用已有台账的流程向同一本账登记数据，业务人员可按来源流程筛选。
2. 配置台账字段和表单。简单登记默认生成可编辑的“登记 → 完成”流程。配置人员可以从节点库拖入步骤、连接分支，点选节点设置字段、状态、审批人和事件。拖动卡片可以整理布局，插入节点或修改连线决定执行顺序。
3. **每本台账发布前必须配好列表显示字段和可查询字段。** 配置人员可以在预览中检查列顺序和查询条件，再为岗位增加命名视图，如“待我验收”。统一台账页和关联页签默认复用台账的已发布视图。
4. 在统一授权入口配置谁能查询、新增、编辑、办理或执行作废等操作，以及每项操作适用的记录范围和字段。业务人员从统一台账页选择有权访问的台账，在相应记录上看到当前可执行的操作。

节点可以保存为带默认参数的模板。多步组合可以发布为声明输入、输出的可复用子流程。画布上的节点属性编辑与子流程输入配置分别可参考 Dify 和 n8n 的交互。[Dify 节点面板](https://www.dify.ai/blog/introducing-trigger) · [n8n 子流程](https://docs.n8n.io/build/flow-logic/break-workflows-into-smaller-parts.md)

平台已有动作可以直接在画布编排，专用算法等新能力可以通过代码注册为节点。高度定制的业务也可以整条用代码实现，产出台账记录时接入统一台账和授权入口，有人工审批时接入统一待办及审批历史。

## 2. 每次保存都有一份业务流配置实例

| 对象或操作 | 约定 |
| --- | --- |
| 保存配置 | 每次成功保存都追加一份不可变的业务流配置实例，即可独立打开、比较和恢复的版本快照。未配完的流程可以保存为草稿。历史可查保存人、时间和来源版本。 |
| 快照内容 | 保存画布布局、节点及连线、节点属性、状态与字段规则、审批人规则、事件订阅与映射，以及引用的台账、事件、视图、关联和子流程的确定版本。打开旧版能还原保存当时的设计。 |
| 发布配置 | 有发布权限的人选择一份已保存版本。发布时校验节点、列表与查询配置、字段映射和版本依赖。台账、流程、事件分别管理版本，相互依赖的变更可以联合发布。订阅按发布的生效点启用。 |
| 发起业务 | 一笔实际业务获得自己的审批实例 ID，绑定发起时已发布的流程和字段规则。新业务使用新发布版，在办业务沿用其绑定版本。每次查看或办理仍按当前有效授权判断。 |
| 恢复旧版 | 将所选快照复制为一个新草稿，保留来源，比较差异后显式发布。已有历史版本及其办理记录均可继续追溯。 |

例如，已有申请按 v12 办理。设计者连续保存得到 v13 和 v14，二者都进入版本历史。发布 v14 后，新申请走 v14。此时恢复 v12 会得到一个来源为 v12 的新草稿。实现时应区分两次独立保存和同一保存请求的网络重传，后者应返回原保存结果。

## 3. 一种台账在流程中怎样办理

| 配置项 | 办理行为 |
| --- | --- |
| 字段 | 台账字段可以用于表单、列表和查询，各节点配置显隐、只读、可编辑和必填。办理字段归属当次操作，例如连续退回三次，每次退回原因分别进入审批历史。 |
| 状态 | 每本台账定义业务状态。节点可在进入、提交、通过、退回等动作上选择目标状态或保留当前状态。例如进入复核为“待复核”，通过为“已确认”，退回为“待补正”。 |
| 审批 | 人员来源可选指定成员、角色或岗位、发起人的部门主管、台账中的人员字段。多人可配置任一人办理、全员会签或按顺序办理。无合格人员时进入“待分派”，由配置的责任人处理。 |
| 走向和记录 | 支持顺序、条件分支、并行与汇合、退回指定节点及按记录逐条办理。默认一次业务在登记节点产生一条主记录，分批业务可配置多条。存在多条候选记录时，明确本次办理的批次、逐条处理或汇总条件。 |
| 人工与自动 | 同一节点可以有多个来源，各自配置条件和字段映射。默认任一来源满足即可触发，必须等多个事实齐备时在画布上明确汇合条件。人工节点可预填并分派待办，自动节点以触发器获授的权限校验、保存并推进。 |
| 改、删与更正 | 草稿可按权限修改、删除。在办记录按当前节点开放字段修改，终止使用配置的撤回或作废动作。已办结记录可按权限更正、作废或归档，保留原记录、原因和经办人。页面显示“删除草稿”“撤回申请”“更正记录”等实际操作名。 |

## 4. 跨流程串接与详情页签

采购申请、批次验收分别配置各自的单台账流程。采购批准事件可发起验收流程，也可以把数据送入已在办理的验收实例。每个流程实例有自己的审批实例 ID。关联保存来源及目标的台账记录、流程实例和触发事件。同一业务可以串起来追溯，详情组件按实际发生的记录关联取数。

- **上游是否等下游**由配置决定。可在发出事件后继续，也可等待关联流程的结果。采购需要全部到货才办结时，可以配置“累计验收数量达到申请数量”。第一批完成后可显示“部分验收”。
- **业务关联发布后自动生成默认页签。** 配置人员可命名、排序、选择组件。单条关系可用摘要组件，多条记录默认用列表组件并复用下游视图。首次验收与复验即使共用验收台账，也可以按不同业务关系呈现。
- **页签默认展示直接下游。** 如采购人员需要追整改，可显式配置“本采购申请 → 验收 → 整改”的关联路径。两张验收单归属于哪条申请、哪一张产生了整改，都应能查清。记录数只统计当前用户可见的关联记录。
- **可以在页签内办理下游业务。** 下游允许人工发起、当前业务已达到触发条件且用户有新增权限时，显示“新增关联验收”，自动带入采购单等关联信息。保存与审批执行验收流程的规则。仅开放算法或接口触发的台账页签提供结果、进度和详情。

## 5. 统一事件引擎与订阅

页面新增、外部接口、算法结果、数值测量、规则命中、其他台账和其他流程都可产生事件。不同来源能映射到同一业务事件类型，例如“检测报告已出具”。每个触发节点都通过统一配置接口查询有权订阅的事件类型，读取指定版本的字段与样例，校验过滤条件和字段映射，并随流程版本发布订阅。

| 场景 | 已确认的处理 |
| --- | --- |
| 事件进入目录 | 台账发布时自动登记记录已创建、状态已变更、记录已作废等标准事件。需要以新增操作发起审批时可提供“新增请求已受理”。“记录已创建”随成功写入登记，提交后投递。配置人员可命名并发布规则派生的事件。 |
| 发起或接续 | 订阅明确选择发起新流程或送入已有流程。接续时按审批实例 ID 或能唯一定位业务的编号关联，有多个样品、批次或待办时再匹配具体目标。已可关联但提前到达的结果按设定有效期暂存，流程到达节点后办理。 |
| 重投与业务重复 | 同一来源的同一事件重投，对同一订阅只产生一次业务效果。人工与接口可能带来不同事件而指向同一份报告，台账按配置的报告编号等业务字段识别。内容一致时沿用记录，有差异时保留来源并交指定人员复核。 |
| 数值触发 | 默认按设备及其规则在首次越限时触发一次，恢复后再次越限可产生下一次。也可配置每次满足都触发，或持续指定时长后触发。配置持续时间时须定义采样中断怎样计时。原始读数和规则产生的“设备持续超温”均可作为事件类型。 |
| 多订阅与连续触发 | 一次事件可以发给多个独立订阅，分别记录结果，只重投失败项。新记录可以继续发布事件，保留因果链。设计器指出可以识别的无退出条件自动回路，合法返工应明确再次进入的业务条件。 |
| 生效与历史 | 新订阅从生效时开始自动处理。补办历史记录时由有权限的人选择范围，预览将新增、已匹配的记录后执行，并使用相同去重规则。原订阅已接收的早到事件和失败重投继续按原订阅办理。 |

## 6. 功能权限与数据权限两个引擎

统一权限入口提供“功能授权”和“数据范围与字段”两个管理栏目。两个引擎分别维护策略、管理权限、版本、发布记录和判定接口。功能管理员和数据管理员可以由不同人员担任，也可由同一人兼任。两侧使用一致的租户、主体、角色、台账和动作标识。部署可以同进程，也可以分别部署、升级。

| 引擎 | 管理内容 | 对业务入口提供的结果 |
| --- | --- | --- |
| 功能权限 | 谁可以对哪个台账或流程执行查询、新增、编辑、审批、配置、发布等已登记动作。角色和岗位按租户分配。 | 对指定动作判定有无资格。动作与授权来源可追溯。页面据此显示可用入口，服务端 API、后台事件办理也核验执行主体的动作资格。 |
| 数据权限 | 在指定动作下，主体可以处理哪些记录、读取或修改哪些字段。范围可按本人、部门、责任范围、本人待办关联和单条临时授权配置。 | 对查询返回行筛选条件和字段读取、筛选、排序规则，对指定记录或拟写入的数据检查行范围、字段及有效期。关联页签按目标台账授权取数。 |

**办理一条记录须同时具有该动作的功能资格和该动作下的记录、字段权限。** 同一租户内，主管岗位可查看本部门，登记员岗位仅可编辑本人，兼岗者可以查看同事记录，修改范围仍为本人记录。对按岗位授予的范围，只合并本台账、本动作下匹配的岗位授权，并保留每个记录范围与可用字段的对应关系。例如用户可读本人记录的采购单价、可读全部门的采购数量，则查看同事记录时只展示获准的数量字段。当前节点的办理资格、字段和状态规则再约束这次操作。

**单条临时授权只扩展数据范围。** 按台账启用后，授权人可指定记录、协作者、动作和有效期。例如授予一张验收单的临时编辑范围，协作者还须具备验收台账的编辑功能资格。数据管理员只管理记录和字段范围，功能资格通过功能授权栏目授予。

两侧独立发布。任一侧收紧或撤销并生效后，后续查询及写入立即按新的交集办理。已打开的页面、在办单和自动节点也使用当前授权。集成时应能追溯一次办理采用的两侧策略版本，并验证策略或角色缓存刷新与撤销提交之间的时序。

列表查询在排序、分页、计数前应用数据范围。有查询功能但可见范围为空时，列表为空、总数为零。详情及关联页签按相同语义处理。新增检查拟写入记录的归属和字段，修改在写事务中重新核验动作、原记录以及拟修改的归属和字段。验收员可以核对采购数量并填写实收数量，采购单价只向获授权人员展示。

## 7. 成熟组件与实际接入边界

组件事实于 2026-11-20 根据官方文档、开源示例及项目源码核对。推荐先验证功能侧 jCasbin、数据侧 Cerbos。两项核心实现均采用 Apache-2.0。该组合可把 jCasbin 嵌入 Java 应用，Cerbos 作为同机或独立部署的判定服务。正式采用取决于各自接入测试和组合验收。[jCasbin 许可证](https://github.com/apache/casbin-jcasbin/blob/master/LICENSE) · [Cerbos 许可证](https://github.com/cerbos/cerbos/blob/main/LICENSE)

### 7.3 数据权限引擎

## 8. 已确认的端到端验收场景

用项目里从未专门开发过的“采购申请”和“批次验收”两本普通台账，由配置人员从空白完成以下操作。表中是预期结果，执行证据留待实现验收时填写。

| 步骤 | 可观察的通过条件 |
| --- | --- |
| 1. 配置并发布 | 两种台账均通过页面完成字段、节点、审批、列表列、查询字段和授权配置。采购和验收各一条单台账流程，业务人员能从统一台账页找到并使用它们。 |
| 2. 事件串接与分批 | 从实际采购申请发出事件，验收流程按关联处理两批。重投同一批的同一事件仍只有原办理结果。采购页签列出实际关联的两张验收单，另一张采购申请的记录只显示在它自己的关联中。需全部到货才办结的采购单在第一批后保持“部分验收”。 |
| 3. 保存、发布与恢复 | 保留一笔在办申请。独立保存两次，在版本历史中可打开并比较两份草稿。发布新版后新申请按新版办理，原申请继续原版。恢复一个旧快照会得到新草稿，经显式发布才对新业务生效。 |
| 4. 多岗位与临时协作 | 使用主管、经办人、临时协作者三个身份。主管可读本部门，经办人按本人或待办行动。兼任两个岗位时按动作分别合并。协作者只获得指定记录、动作、期限及允许字段。核对列表的每一页、总数、详情可见字段、关联页签数量及实际写入结果。 |
| 5. 两侧独立判定 | 先给协作者某单的临时编辑范围，但尚未授予编辑功能，实际编辑请求被拒绝。补授编辑功能后，只允许编辑获授的记录和字段。另选有查询功能、数据范围为空的主体，验证其可打开台账、列表与页签可见记录数均为零。 |
| 6. 两侧独立撤权 | 保持详情页打开、流程在办。一次只收回功能资格，保留单条数据授权，旧页再次提交应被拒绝。另一次保留功能资格，只收回数据范围，同样拒绝写入。收回读取范围时再次查询，列表总数、字段和关联页签同步反映当前授权。 |

功能引擎须验证跨租户的同名角色、新台账动作的动态登记，以及页面、直接 API、后台事件的判定一致性。数据引擎须验证按动作取行与字段、分页前过滤、准确计数和撤权后的写入。两个引擎分别达标后验证组合办理。流程事件组件另以真实流程实例和台账记录验证启动、定向唤醒、早到暂存及失败重投。这些均为正式采用前的待执行验收。
