# MSF 前端 Phase 4 实施顺序

以 dev 923b735 为兼容基线；附件是目标，不是假定前三阶段已经落地。保留租户鉴权、现有 URL、Office 独立构建及既有 gzip 门槛。不覆盖作者工作区。

1. 导航与可访问性：从已授权应用及当前菜单构建工作台导航面板。Cmd/Ctrl+K 自动聚焦，关闭归还焦点。不保存搜索内容、路由或身份。侧栏仅保存一个展开/折叠偏好。把测试接到现有 Playwright `*.e2e.ts`，登录合成身份后再查路由、双主题、焦点、折叠持久化、页面级溢出和可访问性。
2. 工程封板：写与实际代码相符的章程和台账模板。先用现有分页、租户与表单契约验证模板，不接受未经验证的包名、路径、组件参数或全量生成。升级工具先实现真正只读的 dry-run、检查目标版本与完整门禁，再用隔离分支验证主题生成链。
3. Astryx 和 TanStack 底座：先验证官方包、版本、主题产物与逐个依赖的 gzip 增量。主题先小范围分层验证优先级。Router 迁移先保持深链及查询、浏览器历史、租户不匹配的拒绝行为；Query 须验证租户/运行模式隔离和登出清理；Table 从一个代表性台账开始，保护当前键盘选择、分页和无障碍语义。任何一项超过预算均先缩小引入范围，不放宽门槛，不报告已迁移。
4. 每一批通过类型、单测、真实 Chromium/axe 及双模式构建和包体门禁后，开独立分阶段 PR，待评审再进 dev。前批和已有的配置画布、记录流程 PR 继续独立复验；不在这条分支重做它们。
