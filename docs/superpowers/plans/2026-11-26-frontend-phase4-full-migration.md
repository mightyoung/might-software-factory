# MSF Phase 4: 全量迁移与前端性能预算

**决策：** 2026-11-26 木易选择「完成全量迁移，重新定预算」。不再以旧总量为不可变约束，仍通过两种构建的硬门槛阻止退化。不用一次性替换业务层；按可验收切片迁移，再对准确 dev 基线分阶段合入。

## 不变契约
- 既有深链、原始查询参数、前进/后退、另开标签、登录规范化和未保存保护不变。客户端的路由不替代服务端鉴权。
- Query 只管理服务器数据，后台仍控制授权、分页及筛选；缓存不跨模式/会话/租户/适配器、不持久化。切换后旧请求不能显示；403/401、写入后刷新、网络失败与取消各有测试。
- Table 替换实际台账行列模型，不改变按钮、键盘操作、列次序、批量选择、服务端分页/排序及权限。Office 的构建、进入时机与限额独立。
- 在 Mac 隔离 worktree 开发；关联阶段合入须复验最新 dev 和独立评审。不得将实验性合并基线作为可合入分支，也不得只装依赖就宣布迁移完成。

## 任务
1. Table：在 `frontend/src/components/LedgerTable.test.tsx` 先验证同一可见单元格值只读取一次，兼测复选、重排与行详情；用 v9 Table 行列模型重构共享 `LedgerTable.tsx`，继而替换 `PublishedLedgersPage.tsx` 的动态记录表。动态键用业务原 ID，不用数组位置，保留服务器排序与分页。复跑权限历史、普通业务台账和隐患台账的测试。
2. Router：记录 `src/routing/{router,paths,entityPaths}` 和 `App.tsx` 的行为矩阵。为完整地址、重复参数、空白/中文编码、push/replace/back、旧入口、未知地址以及退出覆盖测试；先用兼容边界切换实例，再让 TanStack 匹配实际顶层路由。避免马上把授权与页面业务拆到新 loader 中；不重复处理跳转。浏览器验证直接深链、前进/后退、租户切换和未保存表单。
3. Query：以已通过的普通台账读试验为基础，按会话边界迁移已发布台账、隐患/通用业务台账的服务端读并移除重复 fetch effects；不重试非幂等写，不让自动 refetch 或保留旧结果改变既有行为。先核实际调用和权限再逐页推进。测试乱序、权限失效、写后更新与会话切换。
4. 量化：HTTP、synthetic 分别对迁移前共同基线与完整候选用相同 Node、锁文件、生产打包及 gzip 方法；记录完整 JS/CSS 资源合计（依赖共用只算一次）、冷启动初始导入闭包、各关键路由加载闭包、Office 单独计量，并用 Chrome 验证实际冷加载。生成资源图和每类测量的测试；在实际候选结果上留有限余量，工作台 Office 对话框与编辑器无新增项则不提额。禁止因拆包、改名或跳过路由而少算。
5. 用真正的浏览器入口跑两种模式、生产打包、API 类型校验、全部单测和既有门禁。每个切片独立对齐 dev 开草稿 PR，评审通过/预期行为和体积全部满足再分阶段合入。最后以真实累计基线复跑并记录预算依据。

- 组合验证基线 `36c8439`：HTTP 首屏静态依赖 190499 B JS，工作台合计 204663 B JS。候选两种构建的实测量级：HTTP 首屏约 226.8 KiB、合计约 241.0 KiB；synthetic 首屏约 206.8 KiB、合计约 221.9 KiB。均以一致的 gzip 度量，未使用传输缓存抵扣。
