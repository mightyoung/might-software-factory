# D1：工装主档案的标准读写

前置基线：D0 已独立判定 CLEAR，提交 `c95455a32f96642f4ed59b7da10c19d65751a59d`。本阶段在独立分支 `codex/d1-standard-ledger-20261115` 实施，D0 工作区和旧数据库保持独立。

## 交付与范围

通过一个 `tooling` 应用中的 `tool` 工装主档案，证明标准列表、查询、详情、新建和描述性编辑由公共运行能力和公共前端完成。实体专属内容限定义、存储映射、业务范围策略、迁移、种子和业务测试。普通目录读者无需是保管人；维护者还必须当前负责所选保管范围。

不把借用单、占用、发放、归还、接收、损坏/遗失办理或范围转移放进 D1。页面只表达主档案状态，不声称已有实际可借/在借判定。完整 Q8 变更与冻结后的第二个独立台账成本证明留在 D3。

## 本轮工程决策

- 应用键 `tooling`，实体键 `tool`，动作 `tool.read/create/update`。新标准接口位于 `/api/v1/apps/{appKey}/entities/{entityKey}`，已有 finding/asset/risk 接口不被接管。
- 使用独立定义协议表达 READ/CREATE/EDIT，输入字段不强制属于查询字段。客户端只传业务字段、定义版本和预期聚合版本，幂等键使用既有请求头。服务端拒绝未知和受保护字段。
- 只有服务端启动登记的实体、字段、引用和动作可解析为 SQL。组织、租户、操作者、状态和版本不会从请求取得权限。
- 保管范围有独立业务 ID，关联组织用于标准数据范围判定；它不是部门或用户组的别名。读目录先满足该动作组织范围，再应用目录策略；写入额外检查当前有效保管关系。创建时组织从范围派生，普通更新不能换范围。
- 普通写使用同数据源 RW/READ COMMITTED 事务和既有 root→tenant 命令锁；读使用 RO/REPEATABLE READ。复用 `HumanSessionAuthorityTransaction` 对真实线程、事务和连接的验证，随后核验实时身份、应用、动作与范围。不会启用敏感会话能力，也不会把缺失控制行默认为 OFF。
- 根记录、不可变修订/变更事实、审计和幂等回执在同一事务提交。变更事实包含稳定 event ID、协议/定义/业务版本、命令、主体、时间及快照；重放不产生第二份事实。
- 本轮持久事件承诺是上述不可变变更事实。当前没有实际下游消费者，不创建无职责的 listener、虚假 publication target 或第二套 outbox。真实消费者在 D8 使用既有 Modulith 机制；D1 不宣称完成投递或恢复验收。变更事实写入失败必须使整笔业务回滚。
- 应用/菜单采用业务贡献的登记扩展点；前端只增加一次通用路由和通用解析器，不按 `tool` 写专用页面分支。HTTP 失败不回退合成数据。

## 实施顺序和所有权

1. 公共运行能力 lane 冻结定义、DTO、注册/范围接口、OpenAPI 和回执/修订存储契约，root 与 architect 核查后分发。
2. 公共 lane 实现 `ledger`、中立动作授权、公共审计和应用导航登记；tooling lane 独占新迁移、工装注册、范围策略、精确权限与实库用例；frontend lane 独占通用页面、解析、适配器与路由测试。共用接口变化向 root 汇报后统一调整。
3. 隔离新库验证迁移和运行权限，接通真实 API，之后验证浏览器。所有测试均绑定当前候选源码，D0 基线单独回归。
4. 独立架构审阅、仅变更文件整理及回归完成后，才能判定 D1 通过。
