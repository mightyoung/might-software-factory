# 数据质量与原始数据处理边界 v0.1

2026-10-29，设计建议，未实现或验证。回答“原始数据处理在系统内还是只接有效数据”：**平台负责质量契约、配置、校验和血缘；采集端/网关/独立服务通过可插拔管线执行转换。不是平台完全不管数据，也不是Java主服务包办视频解码和所有清洗。** 此责任边界作为架构建议，具体设备协议与复杂处理器尚未选型。独立可接入的抽帧/数据处理模块已明确纳入本次建设设计，不仅留扩展口；当前仍不编码部署。

## 1 原始到可用的四层
1. 原始观测：来源设备/通道、原payload或文件引用、设备事件时间、接收时间、序号与摘要，凭证另管。
2. 标准化：解析格式、类型、明确单位与时区、映射系统对象ID，保留原值/原单位和转换版本。
3. 质量标注：按具体用途评估缺失、重复、范围、过期、时钟、来源可信度、估算与转换情况；不生成万能“有效=true”。
4. 用途视图：某算法/台账/报警所需窗口、采样/聚合、准入条件；结果引用原始来源及处理版本，消费者决定是否足够适用。

相同数据可适合趋势展示而不适合实时报警。有效不是正确无误，更不等于安全；UNKNOWN必须可传播至事件/报警和页面。

## 2 最小质量契约
|维度|必需声明和处理|
|---|---|
|语义|测量项/信号含义、对象/设备/通道ID、位置/环节映射及版本，不靠自由文本猜|
|格式|类型、schema版本、编码、精度、允许空值/缺省；解析失败保留原因，不填0|
|单位|原单位、标准单位、转换公式/版本；摄氏/华氏、压力等不可混用；未知单位拒绝定量比较|
|时间|eventTime、receivedAt、处理时间、时区/时钟来源、窗口；缺时钟标未知，不以接收时间伪装采样时间|
|完整性|序号缺口、缺失率/长度、连续性、分片齐全；是否允许估算由用途决定|
|新鲜度|每种用途允许年龄、乱序/迟到容忍；最后值仍显示时标STALE，不自动补新时间|
|来源|数据源身份、采集器版本、传感器/校准信息（如有）、完整性摘要；unknown不虚构校准|
|质量结果|flags、规则版本、失败原因、处理链和原始引用，允许多标签并存|

首期最低能力：格式/来源/时间/单位检查、重复标识、缺失/过期标签、显式单位转换和映射验证。复杂去噪、插值、补全、视频预处理、同步校准/融合、模型清洗外置执行，但契约与血缘统一。协议仅宣称能力，设备真实支持要接入测试。

## 3 不可洗掉的异常与缺失策略
物理异常高温/压力/浓度可能恰是重要信号，不能为了“平滑”或通过区间检查删除。区分设备量程/物理不可能值、业务报警阈值和统计离群值：业务超限保留并进入事件评估；量程之外标疑似测量故障并生成数据健康事件，不直接归为正常。

去重用来源+序号或稳定事件键；没有可靠键时标疑似重复，不能靠相同数值删掉持续观测。乱序按事件时间处理、设水位/容忍窗口；过晚数据进入历史修正路径，不未经规则重放实时通知。

插值/估算保留estimated、方法/版本、覆盖区间，默认不得作为安全阈值自动解除依据。缺失/断流/服务失败为UNKNOWN或STALE，不当0、不当无报警。原始值与标准化/估算值分列可追溯；错误映射/转换修正产生新处理版本，不偷偷改历史输入。

## 4 执行与存储责任
采集端适合设备协议解码、时间戳、轻量预检和断网缓存；网关适合协议转换、路由与有界缓冲；独立服务适合媒体/高频/复杂转换。Java控制面校验注册契约、授权、版本、结果格式/映射/质量门槛及血缘，调度持久任务。

原始数据按类型/敏感度/成本/用途配置保留：连续视频可保留受控环形缓存和事件片段，不能默认永存全部视频；时序支持保留/降采样策略。实际时序数据库是否需要依采样频率和保留规模测量决定，首期不擅自新增数据库。需要追溯的安全事件证据按相应保留策略冻结；清理有审批/审计，元数据保留可解释来源已过期，不能假装原始文件仍在。

血缘至少 sourceId/rawRef → processingRun与版本 → normalizedRecord/窗口 → algorithmRun → result/event/alarm → findingId；有文件才计算摘要，不伪填hash。处理幂等、失败可重试、回放隔离实时副作用；原始内容和日志按最小权限/租户隔离。

## 5 官方技术依据及范围
- [W3C Data Quality Vocabulary](https://www.w3.org/TR/vocab-dqv/)：提供描述质量及适用性的框架，不给完整万能质量定义；其地位为Working Group Note，不冒称强制国家/行业标准。本设计借鉴用途适合性和质量元数据，不要求系统采用RDF。
- [W3C PROV-O](https://www.w3.org/TR/prov-o/)：用实体、活动、主体及派生关系表达来源；本设计借鉴血缘语义，不要求部署本体数据库。
- [OpenTelemetry日志数据模型](https://opentelemetry.io/docs/specs/otel/logs/data-model/)：区分事件Timestamp与采集观察ObservedTimestamp。这里用作时间语义参考，不把日志协议当工业传感器质量标准。

## 6 验收和待确认边界
合成输入覆盖单位未知/转换错误、未来时间/漂移、相同值但不同序号、重复回放、缺失窗口、乱序、过期缓存、估算数据、异常高温、来源设备映射变更。断流/失败不得生成无风险结论；原始→处理→算法→隐患链可定位；重放不重复创建真实工单；质量拒绝可解释且保留证据。

以上无清洗效果、精度或吞吐实测。待接入真实设备时核具体协议、采样率、时钟、网络、数据量、留存及安全负责人；这影响适配与成本，不妨碍现在确定通用责任边界。复杂清洗方法不能未经验证自动当事实修正器。

## 7 开发配置与运行配置分离
处理器/adapter及转换函数由开发时注册、测试发布；运行配置可在已注册集合内选处理链、数据源、质量契约、受限参数及输入输出映射。规则版本发布与回退可审计，不能用配置执行任意代码或洗掉异常。抽帧输出来源流/通道、帧序号、采样时刻、画面尺寸/裁剪、处理版本、质量和证据引用，支持下游OCR/视觉算法；抽帧频率与报警判定周期分开。具体执行器库与部署资源未定、未实测。
