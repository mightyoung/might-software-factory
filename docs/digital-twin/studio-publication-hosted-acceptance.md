# Studio 发布与 Player 固定版本：托管验收规格

本规格未执行，不注册工作流、不启用迁移。先完成[适配器前置条件](studio-publication-adapter-review.md)。

复用 `.github/workflows/ledger-configuration-ci.yml` 的托管 PostgreSQL 18、固定 loopback
与 GitHub 只读权限模式，以及 `AuthorizationWriteGuardPostgresIT` 的双连接阻塞观测。
未来使用专用一次性 `studio_publication_test` 库；开测核对库名、版本、表所有者、
FORCE RLS 和应用角色不是 owner、superuser 或 BYPASSRLS，缺项失败而非静默跳过。
初始化管理员、合成权限管理者和应用角色分离；不复制生产角色、授权、数据或凭据。

两个人工租户 A/B 使用同名屏幕；每租户各设合成发布人，另设 A 仅读者和合成撤权操作人。
只使用项目 `backend/src/test/resources/digital-twin/combined-studio-v1-synthetic.json`，
B 首版与 A 第二版各变更一个允许字段。发布者采用真正的人类会话夹具，不用系统身份。
测试直接走受管命令与 Player 适配器，不需要 HTTP。

| 操作 | 验收 |
| --- | --- |
| A 首发，再按当前期望重试同内容，再按旧期望重试 | 新版本 1、无变化、冲突；真提交后只有一条版本、一条匹配真实夹具操作者的成功审计和一个指针 |
| A/B 同名屏幕；A 再发布第二版 | A 当前版返回 2；pin=1 按独立计算的摘要和字节仍返回原版；缺失 pin 不回退；A/B 数据与摘要隔离；仅读者不能发布 |
| 两次同时首发，以及两次从已有头竞争 | 独立连接确认双方 PID 与 `pg_blocking_pids` 后放行；每轮只有一方新增一条版本与审计，失败方不推进指针 |
| 撤权在先，以及合法命令在先 | 撤权先提交时等待方重新核权，业务表及成功审计不变；命令在先时已授权提交可完成，撤权随后提交，下一次命令拒绝 |
| 审计抛错，以及回调完成后提交失败 | 分别测试，不混同；独立观察连接确认版本、指针、成功审计均未变化；客户端不获成功 |
| 最小权限和外键 | 非 owner 历史不能改，异租户看不到行；受限夹具验证复合外键，不将应用角色升为 owner |

等待均有截止时间，失败释放持有连接；不根据 sleep 或回调结束推断已阻塞/提交。
输出仅保留合成检查名、版本和检查结果，不上传载荷、连接信息或凭据。真实 Studio/Player
动作与作用域、受管事务所有者及人类审计投影、隔离 SQL 角色与测试本身缺一不可；
fake 只证明顺序，不证明真实锁、提交、RLS 或字节回读。
