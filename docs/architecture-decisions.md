## 延期且不默认引入

SQLite完整档、Redis、MQ、Keycloak独立服务、S3/RustFS、Kubernetes、多进程微服务、管理员在线表单设计器、移动端。只有实际需求和明确实施范围出现后再引入。

MinIO官方开源仓库已归档；Camunda7 CE停止后续维护；Camunda8生产许可不符合默认无新增商业成本路线。具体证据与限定范围见完整设计，不能泛化为厂商所有商业产品停止服务。

## 必须先验证

1. BOM、Flowable事务/计时器、PG18、jOOQ codegen/runtime、Flyway迁移及Session集成。
2. JDK发行版支持期、逐包SBOM/许可及漏洞；本项目自身许可证尚未选择。
3. 全链路租户隔离、成员撤权、Agent scope、审批参与者授权。
4. 实际并发/数据规模下登录、查询、保存及恢复性能；2核4GB50GB只是试测起点。
5. 上线客户的审计保留、身份联邦、容量与可用性要求。

不使用“AI已生成”或“组件支持”作为实际运行正确的证明。本文无CI结果、性能数据或部署声明。

## 单仓库与目录边界

采用单仓库管理，前端和后端独立构建、独立部署。规划目录：

- `frontend/`：桌面浏览器前端。
- `backend/`：模块化单体后端与其测试。
- `contracts/`：共享API、字段/动作schema、事件版本契约；不放双端混用的运行时业务代码。
- `docs/`：设计、决策、验收及后续运维文档。
- `deploy/`：未来经授权的部署说明与模板，不存凭证。

当前仅README和docs实际落盘；其他目录是已确认的组织规划，不用空占位代码冒充已搭建。单仓库不等于前后端必须同进程、同构建或同时部署；破坏契约的变更仍须兼容窗口与协同发布。

## ADR 013 第一业务样板

选定生产安全双重预防机制（风险辨识分级管控、隐患排查治理、危险源配置）验证公共框架。危险源、风险场景、重大危险源和重大事故隐患分开建模；业务复用公共权限/流程/附件/字段契约，不复制平台服务。

[样板及官方证据](business-samples/dual-prevention-mechanism.md)。标准元数据已核而全文未核的项目不得预填正式字典或计算阈值。行业、地区、规模和真实试用责任人属于正式落地前适用性门槛；先做通用设计及合成演示，不默认把危化或工贸专项用于全行业。AI建议不替代安全专业判定及监管程序。
