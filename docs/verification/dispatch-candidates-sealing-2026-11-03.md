## 实现

受限候选 GET 与实际派单的单成员资格检查复用完整授权 SQL，先过滤资格，再做 UUID 游标分页，不读取全员后逐个检查。调用者范围解析保持原实现。候选仅提示当次资格，实际派单重新校验当前权限、版本、所选成员和任务归属。

读取使用独立只读 REPEATABLE READ 事务、本地租户和默认 2 秒逐语句超时，Spring 事务超时为 5 秒，无命令授权 advisory lock 或业务写锁。事务超时也映射通用、可重试的 503，不泄露原始异常。此配置不保证整个 HTTP 请求精确 5 秒截止。

候选矩阵用实际连接验证只读、REPEATABLE READ、`statement_timeout=2s` 及无自身 advisory lock。新增用例由所有者事务仅锁住 `member_org`，观察 `pg_locks` 与实际 blocker，候选端点快照内 SQL 在超时窗口返回通用503；回滚释放后同一浏览器会话返回200，业务及引擎快照不变。阻塞可能发生于该快照中的调用者授权查询，不声称只验证最后的候选 SELECT；也不声称恢复时借用了同一物理连接。

封存用例在竞争前预置证据，由受控所有者事务遵循共享授权守卫和证据父行锁协议编辑元数据，另一路执行真实 HTTP 整改提交。观察 transactionid 锁与 `pg_blocking_pids`，排除由全局独占授权守卫造成的假竞争。编辑先提交时，提交看见 QUARANTINED 后422，除预期 evidenceRevision 增量外无业务/回执/审计/发布/引擎变化。提交先封存时，编辑等待后被 V6 规则拒绝；核对封存集、条目、提交、快照JSON、文件/回执、任务和重放无重复。这证明数据库封存协议，不证明尚不存在的生产证据编辑、上传或扫描接口。

## 故障、构建和保留

候选首轮25项中21项通过：三个场景因连续登录触发真实来源限流，一个域外范围用例误清空全部范围而得到403。仅修正测试夹具：使用单调测试时钟推进现有额度窗口，域外场景保留指向其他组织的非空范围；生产限流和权限规则不变。它不证明限流容量。授权并发首轮被数据库专属确认门禁挡在启动前，补齐本地独占库的精确确认后22项通过；未放宽预检或增加数据库权限。首次失败日志与后续成功日志均保留。

最终断网 Linux Java21 `clean verify -Plan-postgres-compatibility -DskipITs` 通过552项，失败、错误和跳过均为零，强制安全文件能力检查；包含新增事务超时503和隐私单测。旧551项结果不替代最终结果。已取得前端类型检查、构建和四份生成契约一致检查；332份 Java、资源、契约和构建输入的 SHA256 与实际执行快照相同。独立源码审查无剩余发现；封存测试的失败路径资源清理已按审查意见修复。

全部实库场景后，角色、迁移及追加表 SQLSTATE 探针再次通过，探针写入事务回滚，不删除历史。仅停止本批专用容器，保留数据、内网、镜像和证据。NAS 未连接，PR #16 未处理。
