本批在 `a9cb065c97f22581567050333ed515c9e6edbd76`（PR #42 与 PR #43 的本地依赖合并）上完成版本化定义、Finding 后端与桌面消费者接线。后端完整默认／兼容配置、前端完整测试、生产构建和生成契约检查均已通过。结论限于本批固定源码验证；G013 生产 PostgreSQL、HTTPS 和真实浏览器验收尚未执行，不宣称整个 G013 或 P0–P2 完成。

## 本批行为

- 新增不可变、代码发布的实体／动作定义和有界引用 DTO。目录校验已知字段、布局、动作及引用绑定，以确定性 UTF-8 数据和 SHA-256 生成摘要；没有在线 DDL、任意 SQL、脚本或通用命令分发入口。
- Finding 使用同一发布定义提供原查询 schema 的投影。原 v5 的 22 个字段、18 个默认字段及精确黄金夹具保持兼容；新定义接口独立使用 definition v1。
- 定义接口固定为 `GET /api/v1/entities/finding/definition?use=READ|CREATE`。服务端重新取得当前账号凭据版本、应用版本、身份／成员纪元与组织范围，按 READ／CREATE 分别投影，再评估弱语义 ETag。授权先于条件请求；随机响应元数据不被当作强字节等价证明。
- READ 不发布创建动作、编辑提示或创建引用；CREATE 只发布实际接受的命令输入。11 个后端输入与 7 个桌面控件分离，桌面保留固定 `grade=UNKNOWN`、最多 8 个请求字段；没有新增风险、来源事件或关联隐患 ID 选择器。
- 新增固定组织查询路径 `POST /api/v1/entities/finding/references/report-organization/query`。解析限制为 2048 字节 UTF-8 JSON、100 个 Unicode 码点的关键词、默认 20／最大 50 条及规范 UUID 游标；拒绝重复、未知或强制转换的输入。查询在过滤租户、有效状态和当前组织范围后执行字面搜索与 UUID keyset 分页，只有确有下一页时才返回游标。
- 后端实现拥有固定数据源、事务持有者、物理连接、线程与生命周期的只读 RR 边界。READ 保留原授权器并核对完整当前快照，CREATE 使用固定动作端口；候选查询只接受同一快照内签发的权限对象。源码与单元测试覆盖这些约束，实际 PostgreSQL 同连接和并发快照证明仍待完成。
- 桌面列表、详情和上报表单消费当前服务端定义；组织选择使用分页 HTTP 端口，不下载全组织列表。请求取消、代次检查及账号／成员／租户／权限摘要变化会隔离旧结果。CREATE-only 成员可进入独立上报页；详情保留本次重新授权取得的定义和记录；跨身份的旧记录选择不会被登录或规范化跳转重新读取，冷启动深链接仍保留。

## 审查、修复与保留失败

原生独立审查消息记录了公共契约 R3 的架构 CLEAR、后端 14 文件源码 CLEAR，以及最终前端 28 文件的代码审查 CLEAR。后端之后仅修正两个测试配置和启动仓库清单断言，9 份产品源码保持原审查字节。前端审查发现并关闭三项问题：CREATE-only 入口仍依赖 READ、详情丢弃当前定义、跨身份 URL 重置被登录跳转消耗。本报告引用这些限定范围的审查结论，不虚构独立文件证明或扩大为实库验收。

有界整理检查没有引入额外产品改写。一个不参与授权路径的 LOW 项保留：读取仓库的私有 `read` 字段赋值后未消费；它不影响实际使用的 CREATE 权限对象身份校验。该项已记录，未为无必要整理改写已审查的实现。

失败证据均保留，后续通过结果没有覆盖原始日志：

- 后端首轮 51 项出现 F1／E5：一处断言预期 Integer，而固定 jOOQ 实际绑定 Long；五处错误来自测试 Bean 缺少指定名称。仅修正两个测试配置，保留 SQL、绑定与权限断言。
- 完整默认首轮 870 项出现 F1：启动测试仍预期 27 个仓库，新增仓库后实际为 28。修正数量并显式要求新仓库名称，保留全部原代理、JDBC、模块、H2 启动与 CSRF 断言。
- 兼容轮 Maven 已通过后，归档校验器曾只查找单元源码目录，未识别集成源码目录中的离线守卫。独立 R2 校验器限定两个已批准源码根且要求唯一匹配，重新读取同一份已保存 XML／class／资源；没有重新编译或重跑测试，原校验器和失败记录未改。
- 前端首轮定向 128 项有 3 项旧数组端口回归；后续定向轮另暴露详情测试点击非交互文本及真实会话适配器误显示合成提示。修复实际交互／展示问题，保留投影断言。
- 前端完整首轮为 320 项、306 通过、2 失败、12 pending。两项旧测试要求切换身份后自动读取旧 ID，与已批准隔离规则冲突；新断言仍验证草稿／不确定命令清理，并要求新上下文显式选择后执行新读取与拒绝。mock 集成超时的实际原因是回环监听 EPERM，原启动 Promise 未拒绝监听错误；补齐错误处理并使用已授权本地监听能力，未延长超时或跳过用例，同时更新过时的定义／组织端口。
- R5 的一个租户测试误以为会自动导航到新租户；现先断言旧租户路由拒绝，再显式进入新租户首页和选择记录。没有改变生产导航或权限行为。
