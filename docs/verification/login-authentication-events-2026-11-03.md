## 实现和审查

- 提供方返回已验证主体后立即保留私有请求观察；仅在来源/解析/账号预留均通过后创建 attempt UUID。
- 外层将状态、headers/Cookie 和正文合计限制在16KiB；独立并发预算覆盖 Session 保存、独立事件提交及最终响应放行。登录之外的路由保留异步能力，登录包装器拒绝异步。
- 先完成本地编码，再在整个 Session 过滤链结束后分类。V14 通过独立可写 READ COMMITTED 事务只 INSERT 一次，不对未知提交重试或追加替代结果。
- 受控全局表不使用虚假的租户隔离。未知主体的四个字段全 NULL；已验证主体只能来自生产提供方。没有请求正文、登录名、IP、哈希、Cookie、Session ID 或原始异常。
- 脱敏故障日志仅包含失败阶段、事件分类和异常类型，不附带异常消息/栈或请求值。编码溢出的兜底只捕获明确的预算异常。
- 独立架构/代码审查发现并修复：编码完成前的尾部溢出、原生 Content-Length 残留、全局异步注册影响、窄身份配置缺少生产记录器，以及故障诊断被吞掉。代码问题已关闭；下述最终执行证据已经取得。

成功观察在响应可发布前已提交。审计 INSERT 执行后受控失败会回滚事件，但之前的 Session 仍存在，响应503且无可用认证 Cookie。另一个用例先执行真实 PostgreSQL commit，再受控抛出 JDBC 确认异常：所有者读取到恰好一条 SESSION_PERSISTED 事件，应用仍返回503且不放出认证 Cookie，没有第二次 INSERT。这是受控确认丢失，不是实际网络中断演练。

原早期 Session 保存故障用例明确观察到 finally 再次保存成功的父行和认证属性。事件仍为 SESSION_OUTCOME_UNKNOWN，主体四项与已验证身份一致，响应只发出失效 Cookie；不把该503解释为数据库回滚。另一个晚保存故障明确检查真实回滚，再检查同样保守的UNKNOWN分类。

证据用例消费真实保留文件和签名回执，验证当前ASCII文本夹具内容。缺失和篡改只作用于新建的本例文件，finally 恢复原文件；篡改字节、原始/篡改/恢复摘要和私有诊断保留。metadata/link/item完整记录与回执数量不变。它不证明任意二进制下载、生产上传、实际扫描或完整G4浏览器链。
