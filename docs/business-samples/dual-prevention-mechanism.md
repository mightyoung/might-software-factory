# 业务样板 01：生产安全双重预防机制与危险源配置

状态：研究设计 v0.1；非已实现功能，非企业合规鉴定。核查日期：2026-10-29（UTC）；执行位置：云端。适用国家暂按用户提出的中国国家标准研究；具体行业、地区、企业规模尚未指定。

## 1. 已决定与边界

首个业务样板不是一张“隐患表”，而是危险源识别—风险评估—分级管控—检查—隐患治理—复查—风险复评的闭环。使用公共账号、组织、权限、审批、附件、任务、通知、审计和字段型台账，不为本例复制公共服务。先完成通用对象与示例；行业规则包须核定适用性后启用。

严格分开四个概念：
- **危险源**：本系统登记可能导致伤害的来源、状态或活动及其识别证据；这是产品模型描述，不冒称某国标原句。危险源存在不等于已发生隐患。
- **安全风险**：针对场景与后果的评估记录；同一危险源可以存在多个风险场景和多次评估。
- **事故隐患**：检查/举报/监测等发现的需核实、整改的缺陷或问题；与风险关联，但风险等级不能直接换算隐患等级。
- **重大危险源**：适用专门辨识规则、单元边界及证据后形成的单独判定，不是给危险源勾一个“重大”复选框；也不等于重大事故隐患。

禁止：自动把红色风险判成重大隐患；把整改完成等同风险消失；把所有危险源都按危化品临界量辨识；把 AI 推测当安全专家认定；用软件审批代替监管许可/复产批准。

## 4. 闭环与状态机

### 4.1 风险
识别草稿 → 待复核 → 有效评估 → 管控实施/验证 → 持续监视；变更触发新评估，旧版保留。设备/工艺/原材料/组织职责改变、事故或未遂事件、措施失效、法规版本更新、到期复评均可触发任务。触发是**提醒重新评估**，不自动改分或假定等级下降。初始风险与剩余风险必须标明考虑哪些措施，避免“已计划措施”被当成“已落实”。风险停用须证据与权限，不能为减少统计隐藏风险。

评估方法先提供可替换接口，不宣布LEC、矩阵或某分值全国统一适用。演示可用明确标注“测试用”的矩阵；正式启用须由适用规则/安全管理负责人确认输入、阈值、升级条件及人工覆盖权限。

### 4.2 排查与隐患
计划发布 → 生成任务 → 执行逐项记录 → 异常形成待核隐患 → 分级与临时控制 → 整改/治理方案 → 提交完成证据 → 复查 → 关闭 → 必要时触发风险复评。

隐患主状态：待核实、整改中、待复查、已关闭；另设作废（误报/重复且有理由，保留关联），复查未通过回整改中；重大判定及报告义务是独立维度，不因审批流仍未结束而阻止及时报告。危急发现提供即时通知/处置入口，不能要求先填完复杂表单或等领导审批才处置。

- 延期：申请原因、新期限、期间风险、临时措施、批准人和版本；保留原始期限与逾期事件。内部批准不能改变外部监管期限或消除已发生的逾期。
- 重开：复发或证据不足时建立重开事件并回整改；保留原关闭结论、时间和责任人。新事件独立发生时可新建隐患并以recurrence_of关联，避免无限覆盖旧案。
- 重大隐患：治理方案、报告和复查资料完整性单独校验；需外部评估/复产批准时设置证据门槛和受限状态。关闭软件工单不代表有权复产。
- 并发/重试：乐观锁、命令幂等键；同一检查结果重复提交不能产生两个隐患。报告回执不能覆盖失败历史。
- 统计：分别展示发现、核实、整改、关闭、逾期、重开、未检查数；分母、时间口径公开。不以隐患数量少证明安全好，也不让关闭率成为自动关单条件。

## 5. 配置边界与 AI 入口

首版配置由开发者/AI在代码与审查流程中维护后发布，不做租户现场任意改schema。租户能维护本单位对象、人员、计划及授权范围内参数，不能静默改法定条款、降低强制判断或删除证据要求。

规则包必须显式标记：通用设计规则/企业制度/推荐性标准/强制要求/行业专项/地方要求。适用性不足或规则冲突进入人工处理，不能“选更方便的规则”。正式规则发布需来源、验证人、有效日、测试用例和回滚方案。版本更新评估存量影响，不自动改旧案等级。

Agent 注册只读查询、拟制风险/检查清单、创建待审核草稿等能力；权限与人相同，返回结构化ID、版本及证据。确定重大判定、修改关键措施、批准延期/验收关闭、监管提交保留明确责任人及审批门槛。Agent不可绕过服务直写数据库或自行输出“合规通过”。

## 6. 台账、权限与性能衔接

导航顶层“安全生产”应用，下设风险管控、隐患治理、基础配置等分组；左侧最多两级，详情用路由/关联面板，不继续堆菜单。危险源、风险、隐患不是共享一个巨大表单，而是关联台账。用户可从隐患追到检查项、措施、风险及依据，人员/组织/审批跳转复用公共选择器。

查询按字段类型自动提供文本、枚举、日期区间、数值、引用选择；本例只声明字段配置，不在通用组件写隐患特例。查询历史/个人视图、选择/批量栏、列控制、行操作、分页遵守公共契约。批量派单可允许，批量关闭必须逐条通过权限/状态/证据/职责门槛，并展示失败项，不能静默跳过。

权限包括tenant隔离、组织/区域/责任范围数据权限与动作权限；安全管理人员不自动拥有平台管理员能力。检查、整改、复核、规则发布的职责按岗位绑定，任务分派快照与组织实时信息分开，离职不重写历史。

性能预算为待验证目标而非测试成绩：登录仅取身份/当前应用菜单/所需权限；字典、表单定义按需加载并带版本ETag；列表服务端分页只返回摘要，不带全部附件、流程图或风险链；引用远程搜索，详情分区懒加载。主表以稳定类型列承载状态、租户、责任、期限等高频查询，扩展配置不能使所有查询退化为巨型JSON/EAV扫描；实际索引以查询计划验收。检查批量生成、导入导出、统计及复评影响分析异步执行；不首次登录全表扫描。大子表分页/分段；附件独立上传、有超时与重试；事务不包远端文件操作。不得把Rust/Java语言选择当作避免慢SQL、过量响应或复杂渲染的替代措施。

## 7. 最小合成演示（不用于真实合规判断）

DEMO-UNIT-01：演示搬运区域；DEMO-HS-01：人车交叉作业场景；DEMO-RISK-01：人员碰撞风险（等级先“待评估”，没有默认分值）。DEMO-CTRL-01：经现场负责人确认的隔离/通行管控措施；DEMO-CHECK-01检查该措施是否按确认方案保持有效。

模拟一次检查记录“隔离设施损坏”及测试图片 → 待核隐患 → 有权限人员根据事实和适用规则确认等级（未配置专项规则时保持待判定） → 临时保护措施 → 指派修复 → 提交证据 → 非整改者复查 → 关闭该隐患 → 触发风险复评。危险源仍保留；不能由“已修好一处设施”推断区域整体低风险。

另设测试记录演示延期驳回、复查失败、重开、跨租户访问拒绝和无依据重大判定拒绝。所有测试对象标sample=true，和正式业务数据/报告分隔，禁止导出为企业官方安全报告。

2. 风险—措施—检查模板：任一有效风险可追到评估版本、措施及负责人；变更不覆盖历史；缺数据不能默认低风险。
3. 计划—任务—隐患：检查项不可无结果自动通过；异常关联可追溯；补报不伪造原检查时间；重复事件幂等。
4. 整改—复查—延期—重开：复查失败回整改；权限绕过失败；必需证据缺失不能关单；外部期限不可内部延期覆盖；监管报告提交失败不得显示成功。
5. 规则包/专项判定：行业不匹配不可启用；重大危险源/重大风险/重大隐患字段与统计独立；新旧依据共存可定位；演示数据不混入正式报表。
6. 审计/性能：跨租户越权和附件越权测试；关键动作、Agent建议/审批及前后值留痕；定义代表性规模/并发后测登录、首屏、查询、保存p95、SQL数、响应体、超时率。先记录环境和规模，再定验收阈值；不得凭空报通过或速度倍数。

业务验收必须包含具备相关职责的安全人员审查，与技术单测、集成测试、端到端测试分开。通用引擎可先实现；行业合规包没有可靠来源和审核不能“先上线再补”。

## 9. 只需用户后续决定的真实歧义

当前通用设计可继续，无需为常规字段/公共流程反复询问。正式行业样板之前须确认：
1. 首个实际适用行业及生产活动（工贸具体门类、危化、民爆、矿山等不能相互代替）。
2. 注册/运营地区，以及企业规模；这决定地方补充要求和适用体系标准。
3. 是仅合成演示，还是已有真实企业要试用；若真实试用，由谁作为规则及安全专业审核责任人。

尚不需要用户决定：某个UI按钮叫什么、通用分页方案、角色实现细节。国家标准全文获取/字典逐条核对和专项法规查新是下一步研究门槛，不是已有完成成果。

## 10. v0.2 同日业务范围与流程增量

本节为当前样板明确流程，优先于前述概括状态机，旧文保留。对象增加车间/工房→产线→工艺环节→设备；设备可多环节关联，责任部门分别绑定，设备/环节关联危险源与风险；物理空间不是视频ROI。

**发现→一名人员审批确认→安全部门审批确认→安全部门分派整改任务/隐患整改通知书→处理人整改→提交验收→安全部门验收；不通过回整改，可多轮；通过闭环。** 第一人员确认节点不可省略或与安全部门节点合并。人员解析为一名有效成员，缺配置不随意选人；每轮整改/验收与通知书版本独立保留。紧急处置和依法报告并行，软件闭环不是监管批准。

算法和物联接入产生结果、事件、报警，再经规则只创建待确认发现/通知，不自动认定专业风险或重大隐患。独立抽帧/数据处理模块纳入本次设计，明确标准输入输出、对象/区域、频度、通知对象等级渠道、质量/证据/版本；重复结果不重复建单。开发时注册schema/adapter/动作，运行时在受控集合配置处理链/算法/映射/联动，不在线任意改表。

详见[业务组合配置](../business-configuration.md)和[数据质量](../data-quality.md)。一般制造业通用对象优先，实际行业/地域尚未精确定义，专项标准仍须适用性核验。所有新增为设计、未实现/未验证。
