## 用户新提案：AI 从卫星/实景构造简化厂区
技术可行方向，但属于方案建议非已实现：
- 优先 AI 输出受约束且版本化 SceneJSON（对象 ID、类型白名单、尺寸/位置/旋转、材质键、来源/置信度、人工校核状态），统一 renderer 消费；避免为每个厂区执行任意 AI JavaScript。
- 简单楼体/道路/设备可用参数化方体、圆柱；重复对象实例化，静态几何按空间区块合并，按层级懒加载/LOD；保留轻量 GLB 作为少量异形资产，两条路线可以共存。
- “程序生成一定比 GLB 轻”不成立：应比 draw calls、场景节点、顶点/三角面、材质、纹理、视频解码/传输、构建时间与内存。GLB 是载体而非性能等级；同样几何可具有不同组织成本。
- Three 官方 InstancedMesh 说明相同 geometry/material 的不同变换对象可实例化减少 draw calls；合并几何减少绘制提交但独立移动/操作需另行设计。设备映射需 objectId/instanceId→deviceId，不能用数组位置当永久业务 ID。
- 视频首期可用地图锚点关联的 DOM 视频窗和点击弹窗，共用媒体会话；不要求真实投影贴地或三维纹理。若后续视频贴到 3D 面需额外解决遮挡/角度/画面坐标/拾取/资源释放；16 路显示预算不会因方体模型而自动满足。
- 卫星/实景只能提供可见外形线索，不能擅自推测建筑高度、内部工艺/设备位置。保留来源授权、比例/控制点/坐标系、测量或人工确认、未知高度标记。别把 AI 模型当测绘或安全依据。
- 2D 地图保底，简化 3D 可选增强，不能据本附件把首期变成全 3D。
- 200 并发用户、50 路分析、16 路展示仍须分层压测；本静态审阅不证明任一容量达标。
