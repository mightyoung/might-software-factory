# 普通业务台账可视化配置开发计划

2026-11-20 编制。交付目标是让配置员在浏览器从空白创建并发布“采购申请”和“批次验收”，通过事件串接、分批办理，在采购详情中查看有权访问的验收记录。新增这两本账的全过程无需修改代码、手写数据库迁移或重新部署。复杂业务可以继续通过显式业务命令或注册节点实现。产品依据见[设计确认稿 §1–8](configurable-ledger-workflow-design-2026-11-20.md)。

## 二、实施顺序与交付条件

下表是建议的工作包。按依赖开工、按可观察结果验收，工期在首个纵向用例完成后结合团队投入估算。服务端和页面在同一工作包内交付。第一批可同时推进 A、B 的定义模型及 E 的组件验证；C 的接口联调依赖 A 的基线对齐。

| 包 | 前置 | 交付内容 | 可观察的出口 |
| --- | --- | --- | --- |
| A　开发基线与工装收尾 | 当前 dev、#67 | 对齐权限验证分支；对旧版本借用单分别撤权、停用成员、改变工装可用性，重试发放、归还及接收。 | 实际 HTTP、双连接 PostgreSQL、业务修订和流程记录证明拒绝后无部分提交，已借损坏件可由有权人员归还并接收。补齐 AU-08 及 D2 未签项。 |
| B　配置持久化与版本 | D1 | 给台账、字段、流程、节点、视图分配稳定标识。落地通用记录存储、按类型校验和受控查询；复用已有台账、复制为独立台账都可配置。保存草稿、历史比较、恢复和发布共用版本服务。 | 两次独立保存产生两份不可变快照，同一请求重传只保存一次；恢复旧版生成可比较的新草稿。发布锁定引用版本，校验列表列、查询字段、映射与依赖；联合发布失败时旧版本继续服务。两名配置员竞争保存时可发现冲突。 |
| C　双权限引擎生产接入 | A 的权限基线、B 的稳定标识 | 功能侧接 jCasbin，数据侧优先接 Cerbos。统一管理入口分两栏，分别管理管理员、策略、版本、发布及撤销。统一 HTTP、自动办理与后台主体标识；在数据库分页、排序、计数前应用行条件，逐记录裁剪字段，并在写事务复核拟修改值。 | 真实接口验证按动作合并岗位、租户隔离、本人/部门/责任范围/待办、可过期可撤销的单条授权。查询资格存在而范围为空时总数为零。旧页在任一侧撤权后写入零行；两个应用副本交叉读写也生效。审计能定位两侧策略版本。未支持的查询计划或引擎不可用时受保护操作拒绝执行。 |
| D　从建账到统一台账页 | B；对外办理依赖 C | 实现建账向导、字段/表单、列表列与查询字段配置、岗位命名视图及预览。默认生成可编辑的“登记 → 完成”流程。统一台账页按已发布定义提供列表、详情、新增、编辑和按状态适用的删除草稿、撤回、更正、作废、归档。 | 配置员创建一本空白普通台账，另一业务账号在真实浏览器查询、新增、修改并删除草稿。未发布定义不可办理，已办结更正有原值和原因。两条流程引用同一本账可按来源检索；复制出的台账独立维护配置及授权。 |
| E　统一事件目录与投递 | 组件验证可立即开始；订阅发布依赖 B；办理依赖 C | 隔离验证 Flowable Event Registry 的表结构、启动与定向唤醒，复用 Spring Modulith 事务发布，以 CloudEvents 表达来源、类型、事件 ID 与载荷。提供目录、样例、版本、订阅、条件、映射与发布接口。接入页面新增、台账状态、外部接口、算法、数值、规则及流程事件。 | 真实流程实例验证启动、按审批实例及批次唤醒、早到暂存与过期、各订阅独立重试。事务回滚不投递；重投一次业务只生效一次；异源同业务键冲突可复核。覆盖首次越限、恢复再越限、持续时长与采样中断；支持因果追溯、回路检查、有权限的历史补办预览及按原订阅重试。外部/算法适配有契约测试，真实来源接入留在 D9。 |
| F　可视化流程与办理 | B、C、D 的表单与视图、E 的订阅接口 | 单台账画布支持拖入、移动、插入节点、改连线。节点面板配置状态、字段显隐/必填/读写、审批人、触发来源及映射。支持条件、并行汇合、退回、逐条处理、模板、带输入输出的子流程与代码注册节点。 | 浏览器编辑、保存再打开后布局一致，修改连线会改变办理路径。验证任一人/会签/顺序审批、无合格人员待分派、多次退回分别留痕。节点能从授权目录选择多个事件，分别以人工预填或自动身份办理。在办单沿用原定义，旧页保存仍检查当前授权。 |
| G　关联详情与分批办理 | D、E、F | 保存上下游记录、各自审批实例和触发事件的关联。按关系生成可配置页签，支持排序、摘要/列表组件、指定关联路径、页签内有条件地新增/办理下游。可配置上游继续或等待下游累计结果。 | 用两笔采购申请隔离数据，其中一笔分两批验收。第一批后显示部分验收，达到申请数量才办结；重复事件不新增记录。不同权限主体看到各自可见的记录、页签数量与字段；只允许自动触发的关系展示结果与进度。 |
| H　冻结复用与整体签收 | A–G | 冻结通用实现，由配置员在干净租户完成设计稿 §8 六步。跑完既有 SF 字段演进与 RG 回归，并归档配置版本、代码提交、数据库、API、浏览器和 CI 证据。 | 新建采购与验收期间业务代码、迁移脚本及部署均无改动。若发现必须扩展框架，记录缺口并修复，冻结新版本后换一组未专门开发的普通台账复测。 |

## 三、Astryx 与持续集成怎样随功能交付

- **C、D** 复用已有权限页、台账选取和查询控件，将双栏授权、表单、查询、保存/放弃操作接入 Astryx。每次新增一种交互，同时覆盖实际可访问名称、键盘操作、禁用态和错误反馈。
- **E、F、G** 复用相同的选择器、节点属性表单和详情组件。画布的绘图与连线库在 F 的首个“新增节点 → 连线 → 保存 → 重新打开”用例上比较适配；Astryx 负责周边操作面板与状态反馈。验证窄屏和明暗主题。
- **每个 PR** 运行受影响的后端、前端单测、类型检查、构建、体积预算和 Chrome 用例。权限或查询改动增加真实 Cerbos 与 PostgreSQL 作业，事件改动增加 Flowable 实例及投递实库测试。阶段签收使用真实服务/API 的浏览器会话，分别标明夹具、实库及真实来源证据。

### 已发布定义的业务记录

B、D 已推进到“发布 → 授予业务角色 → 统一台账目录 → 新增、查询、编辑和删除草稿”。已发布台账自动登记四项动作，逐台账授权且受当前组织范围限制。真实 Chrome 和 HTTPS 验证了新版发布后编辑旧记录，以及收回编辑权后旧会话写入被拒绝；实库测试覆盖分页计数、类型筛选、字段投影、请求重传和冲突。[复验说明](../tools/ledger-configuration/README.md)

业务记录当前处于草稿状态。后续接入登记提交、流程实例、节点办理及流程版本绑定时，继续保留现有草稿和历史字段版本。功能与数据引擎独立发布、字段级授权和事件跨流程办理继续按 C、E、F、G 实施。

### 单台账顺序流程画布

F 的首个交付单元支持在配置页插入、命名、移动、排序和删除办理节点。拖动和方向键调整布局，提前或延后操作调整办理顺序。流程与台账结构一起保存版本，恢复和复制沿用已有草稿机制。真实 Chrome 通过 HTTPS 保存、重开并恢复了含节点坐标的 PostgreSQL 快照。[验收步骤](../tools/ledger-configuration/README.md)

后续 F 继续实现节点状态、字段规则、审批人和事件订阅，并验证在办单按绑定版本执行。跨台账关联与分批办理仍按 E、G、H 联合验收。

### 单台账节点属性

配置人员可维护台账的业务状态，分别指定节点进入、提交、通过和退回后的状态，逐字段设置显隐、只读、可编辑或必填。审批来源支持成员、角色、岗位、发起人的部门主管，以及存储成员标识的文本字段。配置同时保存多人办理方式、目标顺序和待分派责任人。目录目标使用 UUID，实际人员解析和任务派发属于流程执行阶段。

节点属性与流程图一起保存、比较、恢复和复制。发布检查状态、字段、目标格式和目标顺序中的重复项。配置页与权限页的 JS gzip 合计预算调整到 10 KiB，以包含新增节点面板；整个工作台仍按 202 KiB 验收。[实库浏览器步骤](../tools/ledger-configuration/README.md)
