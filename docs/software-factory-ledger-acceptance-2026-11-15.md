## 1. 执行环境与通用记录

每批固定候选提交 SHA、未提交差异、前后端定义版本、数据库迁移版本、浏览器版本与环境来源。主从、占用、并发、幂等和撤权检查需要真实 PostgreSQL 与实际命令入口；模拟仓储只能提供补充单元证据。浏览器检查访问同一候选后端。

使用隔离测试环境和明确标注的合成数据，不修改现有开发库。建议最小数据：

- 租户 T1、T2；各有同形业务数据，用于跨租户负例。
- T1 的部门 A、B；借用人 U1、U2；主管 M1 管理 A、M2 管理 B。
- 保管范围 S1、S2；保管人 K1、K2 有效负责 S1，K3 负责 S2。K1 同时具有普通借用资格，用于自办限制检查。
- S1 下至少四件独立工装：可借、已占用、损坏待处理、遗失各一件；正常全链检查另提供足够的可借件。
- 实体定义 V1、V2；V2 包含新增可选字段、标签/布局修改、查询能力扩展及适用主数据的显式必填回填规则。

每个用例保存：caseId、requirementIds、候选版本、前置数据、操作人、步骤、预期、实际、证据位置、PASS/FAIL/NOT_RUN、跳过原因。并发用例记录两个连接的真实交错及最终状态，不使用等待固定毫秒推断已发生竞争。

## 2. 台账、装配与字段变更

| 编号 | 前置与执行 | 必须观察的结果 | 证据 |
|---|---|---|---|
| SF-01 | 冻结公共核心后登记一个普通实体，例如工装类别；新增定义、列映射、迁移及业务测试 | 标准列表、详情、新增、编辑可用；无需实体专用表单/控制器或在公共核心中分支识别实体名称 | Git 差异清单、真实 API/PG、浏览器 |
| SF-02 | 通过新应用登记接入菜单、实体、权限与动作；分别以有权、无权及未开通应用的成员访问 | 有权入口和直接 API 一致；未开通或无权不能依靠菜单路径调用；没有复制身份、组织和授权实现 | 注册清单、接口负例、浏览器 |
| SF-03 | 保存包含多行明细的申请，其中一行引用无权对象、另一行字段无效 | 主记录、全部明细、审计成功事件及版本均不发生部分提交；错误定位具体明细 | 实库事务与请求证据 |
| SF-04 | 在标准保存中注入 tenant、actor、占用状态、流程绑定等受保护字段，或尝试编辑已发放明细 | 拒绝请求；身份来自会话；不可借由通用编辑绕过业务动作；数据库和成功审计无变更 | HTTP/PG、字段规则测试 |
| SF-05 | 两个会话读取同一记录版本后分别修改 | 一个提交成功；过期版本明确冲突，不后写覆盖；保留用户输入供核对 | 双连接 PG、浏览器冲突处理 |
| SF-06 | 从 V1 升级 V2，为工装增加可选描述字段，保留旧数据 | 新字段按声明出现在表单和详情；可保存、读回、按声明查询；旧数据为空，不生成虚构值；无需修改通用前后端实现 | 迁移前后数据、Git 差异、浏览器 |
| SF-07 | 修改字段标签、布局，不修改稳定字段键 | 原值与引用关系不变，查询仍识别同一字段；受影响页面按版本更新，其他应用无需重新加载全量定义 | API、浏览器、定义差异 |
| SF-08 | 为已有字段增加查询、筛选或排序能力，混合本人/部门/保管范围外的数据 | 前后端类型与操作符一致；列表、计数、候选与详情不扩大可见范围；排序及分页稳定 | SQL/真实 API、浏览器 |
| SF-09 | 对当前可维护主数据将可选字段改为必填，先执行有明确来源的回填；另设无法可靠回填的数据 | 可回填记录经验证后收紧约束；无法回填时发布门禁失败且报告记录，不能猜默认值；已冻结单据不被回写 | 升级前后 PG、失败与恢复记录 |
| SF-10 | V1 的未提交页面仍打开时发布不兼容 V2，然后提交；再测试引用失效字段的查询视图 | 明确提示定义不兼容并保留输入；不能静默丢字段或过滤条件；刷新核对后按支持的定义继续 | HTTP、浏览器、定义版本记录 |

SF-01、SF-06 至 SF-09 的“无需修改公共核心”以实际差异证明。若需要新增公共能力，先如实记为未达到本次冻结基线，再完成扩展并用新的普通样本复测，不隐去额外变更。

## 3. 工装全链、事务与异常

| 编号 | 前置与执行 | 必须观察的结果 | 证据 |
|---|---|---|---|
| TL-01 | U1 申请 S1 的多件可借工装；另尝试单内重复和混合 S1/S2 的申请 | 合法申请成功但无占用；重复工装和跨保管范围申请被拒绝，无部分保存 | HTTP/PG、浏览器 |
| TL-02 | U1、U2 均申请同一工装，由有效保管人并发发放两单 | 申请均可存在；只有一单实际占用成功，另一单明确可用性冲突；没有双占用或虚假发放历史 | 双连接实库交错、唯一约束证据 |
| TL-03 | 一单含三件，发放时其中一件已被另一单借走或不可借 | 整单失败；另外两件不被占用，本单没有部分发放、成功审计或完成回执 | PG 事务及完整前后快照 |
| TL-04 | 发放前修改申请明细，与保管人发放旧版本竞争 | 使用最新修订的一方才能完成；旧明细不得迟到生效；修改有不可覆盖的历史 | 实库竞争、修订及回执 |
| TL-05 | 一单发放三件，先申请归还一件，再由保管人接收；之后分批处理剩余件 | 申请归还期间仍占用；接收只影响对应明细；其他两件仍在借，单据未结清；最后一件结清才关闭整单 | 浏览器全链、PG、办理历史 |
| TL-06 | 借用人归还损坏件，保管人按损坏接收；尝试再次申请发放该件 | 借还明细可以结清，损坏状态及责任记录保留；该工装不可再次发放，普通编辑不能直接恢复 | HTTP/PG、浏览器 |
| TL-07 | 保管人为一件未结清工装记录遗失结论；再查询旧单、责任记录及可借列表 | 对应借还明细结清，工装不可借；遗失事实、操作者、结论和责任不消失；结案不是免责 | PG、审计及详情 |
| TL-08 | 对同一待接收明细并发执行接收和遗失结案；重复申请归还同一明细 | 至多一个结清结果；关联待接收请求得到明确终结；不重复释放占用、不遗留可继续办理的旧请求 | 双连接 PG、关联记录 |
| TL-09 | 对发放、接收、遗失结案执行同键同参重放及同键异参；模拟提交结果不明 | 同键同参返回授权允许读取的原结果，同键异参冲突；不重复历史或占用变化；结果不明时不自动换键再次执行 | API、回执与实际提交证据 |
| TL-10 | 撤销未发放申请；再尝试撤销已发放单据，或直接删除关联工装 | 前者保留历史且无占用副作用；后者拒绝抹去借用事实，已发放单据继续走归还/异常；独立工装不被级联删除 | HTTP/PG、引用约束 |

## 4. 资格、组织变化与旧单兼容

| 编号 | 前置与执行 | 必须观察的结果 | 证据 |
|---|---|---|---|
| AU-01 | K1 自己申请借用，再用其保管权限尝试发放、接收和遗失结案；随后由 K2 办理 | K1 三类自办动作均拒绝，即使叠加主管等角色；K2 当前有资格时可以办理 | 逐动作 API、PG 无副作用 |
| AU-02 | 撤掉 S1 中除借用人外的所有合格保管人；借用人和主管尝试办理 | 明确无人可办，原状态保留；不自动通过，不授予主管保管权限 | 浏览器及 API/PG |
| AU-03 | U1、M1、M2、K1、K3 及 T2 成员分别查询工装目录、借用单及各自计数/候选/详情，再调用办理动作 | 目录按已授予目录权限展示可借工装，普通借用人无需保管身份；单据按本人、原部门、保管责任范围可见；办理另查资格和自办限制；跨租户不可见，读权限不推导写权限 | 资源×角色×动作权限矩阵与真实 API |
| AU-04 | U1 的借用单在部门 A 提交；发放后 U1 调入 B，再分别访问旧单 | U1 资格仍有效时可归还本人旧单；M1 按 A 范围查看；M2 不仅因 U1 调入就能看到旧单；历史部门不改 | 调岗前后真实授权及记录 |
| AU-05 | 发放人 K1 离岗或被撤权，K2 被授权接管同一原保管范围 | K1 不再能办理旧单；K2 以当前资格接收；历史发放人仍为 K1；不是修改旧单保管范围 | 撤权/授权 API 与审计 |
| AU-06 | 工装仍在借时请求从 S1 调到 S2；结清后再按授权调整；另让调整与发放并发 | 在借时拒绝调整；结清后允许的调整不回写旧单；竞争结果不出现 S1 借用却由 S2 静默接管的状态 | PG 竞争、旧单快照 |
| AU-07 | V1 申请已提交待发放，发布 V2 新必填字段，再修改旧申请明细、发放并归还；同时新建申请 | 旧申请沿用 V1，修改保存新修订并重校验当前业务资格；可按 V1 归还；新申请使用 V2；V2 不回填旧单历史 | 双版本 API、浏览器、修订数据 |
| AU-08 | 旧版本单据办理期间撤权、停成员或改变工装可用性，分别尝试发放、归还和接收 | 旧字段版本不能绕过当前授权；失去动作资格时拒绝且无部分提交；不可借阻止发放，但已借损坏件仍可由有权人员归还和损坏接收 | 真实授权变更/命令竞争及损坏归还正例 |

## 5. 既有能力与阶段出口

| 编号 | 检查 | 必须观察的结果 |
|---|---|---|
| RG-01 | 对共用身份、导航、授权、文件、审计、事务边界执行受影响回归 | 新工装应用不扩大旧安全业务权限，不改变既有命令、证据和版本语义；失败按实际原因修复，不以历史报告代替 |
| RG-02 | 检查模块依赖及通用代码实体特例 | 公共能力不依赖工装/隐患具体类型；业务通过声明、公开接口和显式动作接入 |
| RG-03 | 收敛迁移在干净隔离库及上一候选副本升级演练 | 唯一迁移序列、校验和及授权正确；已有数据保留与冲突处理可解释；原环境未因演练被重建 |

阶段对应：D0 核实 RG-03 所需基线与契约；D1 覆盖标准读写和字段边界；D2 覆盖 TL、AU；D3 覆盖 SF 的冻结后复用与变更；D4 覆盖 RG 并对选定安全台账补业务回归。

所有阶段均按需要执行类型检查、构建、静态/架构检查及针对性测试。关键 SQL 和事务行为不能仅用内存模型证明；浏览器展示不能仅以 HTTP 调用替代；正常链通过不抵销权限、并发或历史兼容失败。
