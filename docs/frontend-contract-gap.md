# 前端与后端 OpenAPI 契约差异清单（隐患台账 / 上报）

当前 B2-F 检查点：本分支已复用 PR16 `233d04fe214528d771d46f7599745b8f28a6c125` 的 HTTP 会话/台账/上报/命令适配器、组织选择与契约模拟浏览器框架；生成类型仍取当前后端契约。Vitest 限定项目 `src` 测试并保留默认依赖排除，修复工具依赖内 Redocly 测试被误收集的问题。未知 API 模式不再静默进入合成演示，HTTP 错误不回退合成数据。

下面原状态和一至七节为早期对齐记录，其中“没有 HTTP 适配器/后端端点契约”等说法已被后续实现覆盖。后续差异表和本检查点描述当前候选，不把历史测试数量当本轮结果。**HTTP 适配器已改读权威 bootstrap/menu，删除静态应用与权限兜底；finding.read/create 显式映射 UI 权限，未知权限不授予。B2-N 真实数据库验收仍独立推进；G2a/G2b 不在本批宣称通过。** 真实后端、Secure Cookie、PG/Flowable和完整业务事务仍须独立验证。

历史状态（仅供追溯）：本地集成分支基于远端 `dev` `6b0c2ee55741f9dd610742dd0e277288534ac432` 的源码树，包含 session、reportable organizations、finding.create、确认人隔离与统一错误契约；对应代码正通过 Draft PR #9 评审。当前本地后端 Surefire 175 项通过；LAN PG18 profile 的安全静态测试 12 项通过、58 个测试源编译通过；锁定生成器 `gen:api` / `check:api`、TypeScript typecheck 与 Vitest 176 项通过。以上本地/合成结果不代表本分支连接了 PostgreSQL；本地没有运行真实 API、完整 Flowable 事务或前后端联调。前端仍使用合成适配器，没有 HTTP 适配器。

## 六、已商定的设计口径与实施顺序（2026-10-31，**设计口径，不表示代码已支持**）

实施顺序：不再把真实联调放到最后。先用真实数据库打通最小闭环“登录 → 当前用户与可用组织 → 创建 → 列表 → 详情”，再逐步加字段、历史和派单；每加一段做一次真实联调。契约由后端负责，前端从契约生成类型、使用模拟服务，CI 检查契约漂移。最小闭环暂不含附件，页面会明确说明。

**业务安全**

- 确实不成立：新增“不成立关闭”出口，必须填写理由，保留记录和审计；“退回补充”只用于信息不足。
- 上报人不得确认自己上报的隐患（含组织确认与安全确认），兼任角色不豁免；两阶段确认人必须不同。此身份隔离规则已在本地后端实现并通过单元/HTTP 测试；无人符合条件时阻断，不自动放行。真实 PG18/Flowable 并发验收仍待进行。
- “需立即处置”必须配通知（通知该组织配置的安全值班人员，记录送达、确认与失败，无人确认时升级）。通知闭环落地前，前端保留醒目的现场应急提示，**不显示“已通知”**。接收人、渠道、升级时限另行配置。

**接口契约（PR #9 的本地集成批次；Draft 待评审）**

- 创建响应返回 `findingId`、`code`、`state`、`roundNo`、`version`；`backfill` 暂不定义，补报阈值未经确认。
- 安全确认提交“等级 + 意见”；人员确认、不成立关闭及各种退回均携带意见，拒绝或退回理由必填。
- 来源枚举、紧急程度、24 小时补报和 7 天幂等保留期仍是提案，本轮未加入生产契约或实现。
- 紧急程度建议 `NORMAL`（普通）/ `URGENT`（需立即处置）：**两档**，与现有前端三档（含 `IMMEDIATE`）不同，契约定稿后前端改为后端枚举。紧急程度与一般 / 重大等级分开。
- 编号按服务端接收上报的北京时间日期生成，不按发现日期；列表按创建时间和稳定 ID 排序，不按编号字符串排序。
- 幂等：完整响应至少保留 7 天，之后保留标识到原记录的映射；过期重试不得静默新建，同标识不同内容返回冲突。
- 补报由后端计算（建议发现时间距提交超过 24 小时），阈值写入契约。
- 新建入口以“可上报组织列表非空”为条件；权限标识直接使用后端的 `finding.create` 等；403 后刷新用户、组织和菜单。

**前端待办**：接入真实 HTTP adapter 和组织选择（单个自动选中但仍展示，零个则不显示入口并说明）；创建结果展示服务端 `code`；呈现后端字段错误和冲突子码；补报展示要等阈值与持久字段定稿；新增“不成立关闭”等操作入口；菜单和权限改用后端标识。
