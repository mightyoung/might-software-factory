# Might Software Factory

前后端分离的 B/S 软件工厂基础框架：让 AI 与开发者在统一公共能力、数据模型和发布规范内构建业务系统。

## 当前状态

**设计文档初始化，尚未实现或部署。** 当前公共服务方案为 v1.1（2026-10-29）。本仓库未提供运行中的服务、应用构建、测试结果或性能验证；后续开发应先通过兼容和隔离门禁。

## 设计方向

- 公共能力、业务、展示三层；纵向语义与能力登记服务页面和受限 Agent。
- Java / Spring 模块化单体，PostgreSQL 完整功能档，jOOQ，嵌入式 Flowable。
- 首期数据库持久会话、私有本地文件、站内通知和持久任务；不强制 Redis、MQ、Keycloak 或对象存储集群。
- 第一版台账由 AI/开发者代码配置，审查、测试后发布；不做管理员在线加字段即时生效。
- 首期仅电脑浏览器；最小登录加载，其他应用/表单/字典按需获取。
- 后端最终鉴权覆盖所有入口，Agent 不直连数据库。

Spring Boot 4.1.2、Modulith 2.1.1、Flowable 8.0.0 是设计基线，**组合尚未构建验证**；Flowable 发布依赖基于 Boot 4.0.2，需先做集成测试。具体依赖锁和 SBOM 待实施形成。

当前上传仅为已授权设计文档，不能据此推断业务代码开发、采购、云注册或部署已完成/获批。本项目许可尚未确定，本仓库未新增 LICENSE；引用组件的许可不等于本项目许可。

## 单仓库与目录边界

采用单仓库管理，前端和后端独立构建、独立部署。规划目录：

- `frontend/`：桌面浏览器前端。
- `backend/`：模块化单体后端与其测试。
- `contracts/`：共享API、字段/动作schema、事件版本契约；不放双端混用的运行时业务代码。
- `docs/`：设计、决策、验收及后续运维文档。
- `deploy/`：未来经授权的部署说明与模板，不存凭证。

当前仅README和docs实际落盘；其他目录是已确认的组织规划，不用空占位代码冒充已搭建。单仓库不等于前后端必须同进程、同构建或同时部署；破坏契约的变更仍须兼容窗口与协同发布。

## 当前测试环境决定

最新测试环境决定：已连接MacBook Air仅运行Java管理后台；PostgreSQL和Redis使用局域网外部服务，禁止据本设计在Mac安装/启动PG、Redis容器或视频算法。局域网地址、端口、版本、库名、权限与凭据尚未提供，接入阶段通过安全配置使用专用测试库/账号，不复用其他项目凭据。媒体/算法执行环境尚未确定，云资源暂不申请。50路分析和16路展示仍是系统设计目标，不代表Mac的承载结论。当前没有安装、停服务、开放端口或部署；硬件/既有服务只读盘点另行记录。Redis为当前环境明确的外部组件，不改变公共框架设计中‘无需强依赖’的可选技术边界。
