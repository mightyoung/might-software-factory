## 设计方向

- 公共能力、业务、展示三层；纵向语义与能力登记服务页面和受限 Agent。
- Java / Spring 模块化单体，PostgreSQL 完整功能档，jOOQ，嵌入式 Flowable。
- 首期数据库持久会话、私有本地文件、站内通知和持久任务；不强制 Redis、MQ、Keycloak 或对象存储集群。
- 第一版台账由 AI/开发者代码配置，审查、测试后发布；不做管理员在线加字段即时生效。
- 首期仅电脑浏览器；最小登录加载，其他应用/表单/字典按需获取。
- 后端最终鉴权覆盖所有入口，Agent 不直连数据库。

## 版本与实施边界

Spring Boot 4.1.2、Modulith 2.1.1、Flowable 8.0.0 已纳入后端构建；Flowable BOM带入的Spring Framework/Security版本曾造成架构测试运行时`NoSuchMethodError`，现按Boot 4.1.2 BOM显式对齐，修复证据见[ADR 023](docs/architecture-decisions.md)。本地代码/模块检查不等于应用启动、PG迁移、流程事务或定时作业通过；这些依赖真实PG18的检查仍待执行。CI只跑无数据库测试。完整状态见[P0工程基线](docs/p0-engineering-baseline.md)。

当前分支含P0工程骨架和测试门禁；公共业务能力、数据库生产迁移、API实现仍未完成，不能据此推断P0结束，亦不包含采购、云注册或生产部署授权。本项目许可尚未确定，本仓库未新增 LICENSE；引用组件的许可不等于本项目许可。

## 单仓库与目录边界

采用单仓库管理，前端和后端独立构建、独立部署。规划目录：

- `frontend/`：桌面浏览器前端。
- `backend/`：模块化单体后端与其测试。
- `contracts/`：共享API、字段/动作schema、事件版本契约；不放双端混用的运行时业务代码。
- `docs/`：设计、决策、验收及后续运维文档。
- `deploy/`：未来经授权的部署说明与模板，不存凭证。

本节定义目录职责，不报告代码交付状态；P0已获实施授权，实际实现及验证结果以代码提交和测试证据为准。单仓库不等于前后端必须同进程、同构建或同时部署；破坏契约的变更仍须兼容窗口与协同发布。
